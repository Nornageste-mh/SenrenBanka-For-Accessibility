# SenrenBankaForAccessibility

本仓库是**专门针对 Steam 游戏《千恋＊万花》（Senren＊Banka，AppID 1144400）** 的屏幕阅读器
辅助补丁 —— 一个游戏内 **krkrz / 吉里吉里 Z 的 V2Link 插件**（`a11y.dll`），
文字直接交给读屏 DLL（Tolk / NVDA Controller Client / 争渡读屏 ZDSR / Windows SAPI），
界面用键盘导航，通过向游戏自己的派发发真实鼠标点击来实现。

- 当前版本：**0.2.0.0**（见 `CHANGELOG.md`；这一版是**文档与发布治理对齐版**：
  按 Framework 0.2.7.3 补齐交互形态判定、操作约定、项目状态与发布自检；
  界面操作仍是**遗留导航模式**，不是合规范本，见下面的「交互形态判定摘要」）

## 说明

本补丁的作用：让使用读屏软件的玩家，也能基本正常地游玩《千恋＊万花》。

- 游戏里的控件**不是 Win32 控件，是 KAG 的图层** —— 对读屏软件来说整个窗口是一片空白。
  补丁自己在窗口过程里接管按键，把「按一下」翻译成对目标图层的**真实鼠标点击**
  （走游戏自己的派发），所以**不需要读屏软件做任何特殊适配**。
- 朗读剧情：说话人 + 台词。**有配音的台词不再叠一层 TTS**（人声已经在读了），
  但按 `Backspace` 仍能把这一句念出来。
- 朗读选项，并用数字键 `1`–`9` 选择（用的是**游戏自己给的按钮矩形**，不是猜的坐标）。
- 界面控件可用方向键浏览、`Enter` 激活；但**需要先按 `Tab` 进入导航模式**
  （遗留形态，见下文「交互形态判定摘要」与「遗留：界面导航模式」）。
- 界面标签跟着**游戏的界面语言**走（游戏有三套语言设置：主要语言、字幕语言、界面语言，
  控件跟的是第三套）。
- 语音后端按 `Tolk` → `NVDA` → `争渡读屏（ZDSR）` → `SAPI` 逐级降级；
  按 `Alt+Shift+F9` 可以在**当前可用**的后端之间循环切换（下次启动保持），详见
  [语音后端与切换快捷键](#语音后端与切换快捷键)。

**平台**：Windows x86。游戏是 32 位进程，所以补丁和 `nvdaControllerClient.dll` 都必须是 32 位。

## 交互形态判定摘要（第 0 条纪律）

完整判定见 [`docs/交互形态判定.md`](docs/交互形态判定.md)（随仓库入库；判定口径是
「只看游戏自己读不读、写不写某个东西」，不是「补丁想不想用」）。

- **结论：C 类 —— 游戏没有界面控件模型，补丁调用游戏自己的命中/点击派发来制造键盘操作。**
  游戏里没有 Unity 那种「焦点 / Selectable / EventSystem」；KAG 界面全是图层，
  读屏软件看到的是一个空白窗口。补丁能做的只有：枚举可点的图层 → 自己维护一个选中项 →
  向游戏窗口发**真实鼠标点击**，让游戏自己的派发决定点中了谁。
- **遗留形态（如实登记，不是推荐做法）**：界面操作需要先按 `Tab` 进入导航模式
  （反模式 X1/X9）；选中项是补丁自己维护的（X2）；控件靠 40px 网格扫屏猜（X4）；
  激活靠合成鼠标消息（X6）。这四条都登记在 `docs/交互形态判定.md` §5。
  **本版不迁移**，理由与迁移可行性见该文件 §1 与 §5。
- **已实测能用的路径**：标题菜单、进入正片、打开回想、选中存档槽，都是「补丁发鼠标点击 →
  游戏自己响应」。**第 1 级入口本轮探针已打通**（`layer.onMouseDown`+`layer.onMouseUp`、`SystemAction`、`kag.menu` 项 `command`；存档槽位点击仍不通），但本版尚未迁移。
- **遗留缺陷清单**（与 `docs/交互形态判定.md` §5、`docs/project_status.md` §5 保持一致）：
  Tab 模式；补丁自己维护选中项；网格扫屏；合成鼠标点击；
  破坏性控件无二次确认；设置显示类选项当前值读不出；滑条不念实际值；部分标签不四语齐全；
  争渡后端未实机验证；非导航 `Space`/`Enter` 补点击可能双触发。

## 安装（仅限正版玩家）

安装 = **替换 `data.xp3`** + 往 `plugin\` 放几个文件。
被替换的 `data.xp3` 由发布包里的注入工具**在你自己的机器上、用你自己买的那份原档生成** ——
本补丁**不发布改好的归档文件**，理由见 `docs/DESIGN.md` 第 17 节。

**为什么非得替换 `data.xp3`**：本作引擎不会自动加载 `plugin\*.dll`，
插件必须由脚本显式 `Plugins.link("a11y.dll")` 拉起；而唯一能保证在插件加载前
执行到我们代码的位置，就是 `data.xp3` 里的 `startup.tjs` 槽位。
外挂补丁档（`a11y.xp3` / `patch0.xp3` / `patch.xp3` / `patch_extra.xp3`）
与散装同名脚本我们**全部实测过，一个都不生效**，清单见 `docs/DESIGN.md` 第 16 节。

**请先备份你自己的 `data.xp3`**（约 985 MB，改名为 `data.xp3.bak` 即可）——
这是唯一的还原手段。

步骤：

1. 双击发布包里的 `tools\注入工具.exe`，选你的 `data.xp3`，它会生成 `data.patched.xp3`
   （约 985 MB，4.5 秒）。
2. 把 `data.patched.xp3` 改名成 `data.xp3` 覆盖回去。
3. 把发布包 `plugin\` 里的文件拷进游戏的 `plugin\`：

```
<游戏目录>\plugin\a11y.dll
<游戏目录>\plugin\nvdaControllerClient.dll         ← NV Access 官方 x86 版（随发布包含）
<游戏目录>\plugin\ZDSRAPI.dll                      ← 争渡读屏 32 位（随发布包含，兜底用）
<游戏目录>\plugin\ZDSRAPI_x64.dll                  ← 争渡读屏 64 位（随发布包含，兜底用）
<游戏目录>\plugin\a11y_labels.ini                  ← 可选，覆盖内置标签表
<游戏目录>\plugin\a11y_labels_{jp,en,tw}.ini       ← 可选，其它语言的标签表
```

`ZDSRAPI*.dll` **不用管**：机器上装了争渡就优先读它自己那份，包内这两个只是「找不到 / 版本对不上」
时的兜底。**不用争渡、或者不想让补丁带这两个文件，直接删掉即可**，行为回到「只读争渡安装目录」。

发布包在 GitHub Releases 里（`SBA11y-<版本>-installer.7z`，约 586 KB —— 0.1.0.6 起包里带上了
两个争渡 dll，此前约 174 KB），
含注入工具、插件本体与第三方许可证。**包里不含任何游戏文件。**
`注入工具.exe` 不是 PyInstaller 打包的，是 .NET Framework 自带编译器编的原生程序
（19,968 B，不打包、不自解压），源码见 `tools/inject_boot.cs`。

### 不用 exe，直接从源码生成

发布包里的 `注入工具.exe` 就是 `tools/inject_boot.cs` 编出来的成品
（`tools/build_injector.ps1` 负责编译）。想自己看一遍、或者用 Python 走同一套流程：

```cmd
rem 1) 注入。启动脚本字节码已随仓库提供（data\startup.tjs.bin），不需要 tjs2c
python tools\inject_boot.py --data "<游戏目录>\data.xp3" ^
                            --bin data\startup.tjs.bin ^
                            --out "<游戏目录>\data.patched.xp3"
```

`tools\inject_boot.py` 只有标准库依赖。`--bin` 省略时默认用仓库里的
`data\startup.tjs.bin`；`--script` / `--tjs2c` 只用于从上游源码重建。
它只替换 `startup.tjs` 一个条目，其余内容原样拷贝，内层索引**逐字节照抄** ——
这一条是硬约束，重建索引会静默丢文件（见 `docs/DESIGN.md` 第 16 节）。

`data\startup.tjs` 是**说明文件**（不是 TJS 源码）：字节码 = krkrz 标准 `startup.tjs`
加一句 `Plugins.link("a11y.dll")`；来源、校验值与重建步骤写在该文件里。
**干净克隆可以直接重建 `注入工具.exe`**，不再依赖外部的 32 位 `tjs2c`。

## 主要快捷键

> **本补丁不改变游戏本身的键盘行为。** 下面只列游戏原生键与朗读侧热键；
> 界面操作属于「遗留导航模式」，单独列在后面。

| 键 | 作用 | 归属 |
|---|---|---|
| `Space` / `Enter` | 推进剧情 / 确认（游戏原生） | 游戏 |
| 按住 `Ctrl` | 快进；遇到选项自动停手并把选项念出来 | 游戏（补丁只补念当前句） |
| `R` | 打开历史 / 回想（游戏原生） | 游戏 |
| `Backspace` | 重读上一句（非导航模式下） | 补丁 |
| `1`–`9` | 选项场景：选择对应选项 | 补丁 |
| `Alt+Shift+F9` | 循环切换语音后端（自动 → Tolk → NVDA → 争渡 → SAPI），念出结果；键位可在 `plugin\a11y_speech.ini` 里改 | 补丁 |

**游戏原生占用键**：`Space`、`Enter`（含小键盘）、按住 `Ctrl`、`R`、鼠标（移动 / 左键 / 滚轮）、
`F12`（Steam 截图）。补丁**不抢这些键**，也不把它们拿来当重读键。

### 遗留：界面导航模式（`Tab`，**不是推荐做法**）

> 这一段是**遗留形态**，为兼容 0.1.x 的操作习惯而保留；框架的默认约定是
> 「界面一打开键盘就直接可用，不需要模式键」。本作的迁移计划见
> [`docs/交互形态判定.md`](docs/交互形态判定.md) §5。

| 键 | 作用 |
|---|---|
| `Tab` | 进入 / 退出导航模式（遗留） |
| `↑` `↓` | 选择控件（念出名称与 `i / N`） |
| `Home` / `End` | 首项 / 末项（补丁额外提供） |
| `PgUp` / `PgDn` | 前后跳 5 项（补丁额外提供） |
| `Enter` / `Space` | 导航模式内：激活当前控件；非导航模式 = 游戏原生推进 |
| `←` `→` | 调整滑条类控件 |
| `Esc` | 退出导航模式 |

### 语音后端与切换快捷键

补丁启动时按 `Tolk` → `NVDA` → `争渡读屏（ZDSR）` → `SAPI` 的顺序找后端，
找到一个就用；任一级失败都只降级，不报错、不中止。

- **争渡排在 NVDA 之后、SAPI 之前**：原来用 Tolk/NVDA 的机器行为完全不变，
  只装争渡的机器才落到这一级（这类机器过去在三级链上大概率一片安静）。
- **争渡的可用性判据是 `GetSpeakState()` ∈ {3 正在朗读, 4 空闲}，不是 `Speak()` 的返回值** ——
  未授权时 `Speak()` 照样返回 0，只看它就会「插件自称正常、玩家一声不响」。
- **dll 先找玩家自己装的那份，找不到才用随包的兜底副本。** 候选顺序：
  ①注册表卸载项里 `DisplayName` 含「争渡」的 `InstallLocation`（HKLM 的 32/64 两个视图 + HKCU），
  ②默认安装目录 `%ProgramFiles(x86)%\zdsr\zdsr`、`%ProgramFiles%\zdsr\zdsr`，
  ③游戏目录的 `plugin\`（随发布包那份），④游戏目录根。
  **装过争渡的机器永远走它安装目录里那份**（跟着争渡一起升级），包里那份只是够不着时的兜底；
  尾部这 4 条是**预留**的：注册表登记再多（最多 8 条）也挤不掉它们。
  环境变量 `A11Y_ZDSR_DIR` 可以钉死搜索目录，多个用 `;` 分隔，**设了就只试写的这几处**
  （排查用：用来确定到底哪一份 dll 在出声）。
- **某一份 dll 版本对不上时会自动换下一份。** 官方说过「尽量不要复制 dll」——旧副本会踩
  `InitTTS = 1`（版本不匹配）。所以候选的 `InitTTS` 返回 `1` 时**不停留、立刻试下一个候选**；
  全都报 `1` 才判「不可用」，并给出人话理由 + 试过的路径（同一份只念一遍 —— 这段是念出来的，
  不会出现「装了争渡却一声不响」）。
- `Alt+Shift+F9` = 循环切换：**自动** → `Tolk` → `NVDA` → `争渡` → `SAPI` → 回到**自动**。
  **当前不可用的后端会被跳过**，并在播报里说明跳过了哪些；结果用**新后端**念出来；
  选「自动」时会连当前实际用的是谁一起念（例：`语音后端：自动（当前 SAPI）`）。
  旧版是单按 `F9`，0.2.0.0 起改为 `Alt+Shift+F9`，与框架约定一致、也避开别的软件抢 `F9`。
- 切换结果会写回配置文件，下次启动保持。

配置文件 `plugin\a11y_speech.ini`（可选，UTF-8；模板见 `data\a11y_speech.ini`）：

```ini
key=Alt+Shift+F9     # 与别的软件抢组合键时改这里；主键限 F1..F24、A..Z、0..9
backend=auto         # auto / tolk / nvda / zdsr / sapi，也可写「自动」「争渡」
```

- 键的检测走插件本来就有的 200 ms 定时器（读键状态）：**不要求插件窗口有焦点、也不吞键**
  （游戏自己若也响应这个键会照旧响应）。只有游戏窗口在前台、且不在快进中时才动作。
- `backend=` 里写死的后端**当时不可用时会自动回退**到自动链上的其它后端（诊断日志里有一行
  `指定的语音后端不可用：…`），不会静默变成「没有声音」。
- 修键位/后端不用重新编译：改 `key=` 之后重开游戏生效；`backend=` 一行由插件自己维护。
- **未实机验证**：本机没有启动游戏，所以「争渡在真实游戏进程里真的出声」这一条**没有验证过**。
  已验证的是 32 位构建、导出表，以及用桩 DLL 机械跑通的加载顺序、注册表查找、版本不匹配时换候选、
  可用性判据、文本与打断标记透传、失败降级（`tools\zdsr_selftest\`，85 项断言全过）。

## 已知问题 / 注意事项

- **本补丁不改变游戏本身的键盘行为**：`Space` / `Enter` / 按住 `Ctrl` / `R` / 鼠标等
  游戏原生键照旧由游戏处理；补丁只新增朗读侧热键（`Backspace`、`1`–`9`、`Alt+Shift+F9`）
  与**遗留**的界面导航键（`Tab` 等，见上文）。
- 界面操作**仍需先按 `Tab` 进入导航模式**（遗留形态，不是推荐做法）；
  这是本作目前最大的不合规处，完整遗留缺陷见「交互形态判定摘要」。
- 设置界面**显示类选项的当前值读不出来**（念得出选项，念不出当前选的是哪个）；
  能读到值的只有 `kag.afterskip` `afterauto` `voicecut` `voicecutpage` `bgmdown`
  `noeffect` `sysnoeffect` 这 7 项。
- 滑条只按百分比点击，没有念出游戏实际显示的值。
- 存档界面的翻页按钮、自定义按钮排列界面、记忆界面的部分按钮，
  标签还不是四语齐全，退回中文或位置说法。

  这一条没有验证过。已验证的是 32 位构建、导出表，以及用桩 DLL 跑通的选路与失败路径
  （`tools\zdsr_selftest\`，85 项断言）。
- 补丁的文字是**逐屏实机截图取证**来的，不是从游戏资源里解出来的。

## 构建

只需要一样外部东西：Visual Studio 的 32 位命令行环境。
编译所需的 TJS2 接口头文件**已经随仓库提供**（`third_party\tjs2`，见 `third_party\README.md`）。

```cmd
set VCVARS="C:\Program Files\Microsoft Visual Studio\...\VC\Auxiliary\Build\vcvars32.bat"
build\build.cmd
```

产物是 `a11y.dll`（导出 `V2Link` / `V2Unlink` / `GetModuleThreadModel`）。
想改用自己的一份头文件，设 `TJS_INC` 覆盖即可。

**默认是发布构建**（release，不含任何开发通道）；`build\build.cmd dev` 是**开发构建**
（定义 `A11Y_DEV`，带 REPL 命令通道与 `D:\a11yb` 诊断日志，**不要发给玩家**）。
发布构建里开发通道是**编译期不存在**的，DLL 字符串里没有 `a11yb` / `sba11y_cmd`
（`tools\make_release.ps1` 会机械断言）。

构建脚本**强制 32 位**：先用 `vcvars32.bat` 设下的 `VSCMD_ARG_TGT_ARCH` 判一次，
链接时再带 `/MACHINE:X86`。用 64 位环境跑会**直接失败**，
而不是像以前那样报 `BUILD_OK` 却产出一个装不上的 x64 DLL。

ZDSR 后端的机械自检（可选，需要同一套 32 位 MSVC）：

```cmd
tools\zdsr_selftest\build_and_run.cmd
```

它会自己编**两份**桩 `ZDSRAPI.dll`（一份返回码由环境变量控制、一份固定报版本不匹配 `InitTTS=1`，
两份都逐次调用写日志），再跑 32 位断言程序，**85 项全部通过**，覆盖：

- 加载与候选顺序：dll 不存在 / 未授权(state=2) / 正在朗读(3) / 空闲(4) / `Speak` 返回 2 /
  中途掉线 / 缺 `GetSpeakState` 导出；
- 注册表自动发现：在 `HKCU\Software\SBA11yZdsrSelftest\<pid>\Uninstall` 里**真的写**一条
  卸载项，再断言被测代码把它的 `InstallLocation` 排在候选第 0（`争渡读屏` 优先于只含 `zdsr` 的
  挂钩工具目录），随包那份排在第 5、游戏目录根最后；注册表读不到时候选表照样成立；
  注册表**塞满到上限 8 条**时，尾部四条（`%ProgramFiles(x86)%` / `%ProgramFiles%` /
  游戏目录 `plugin\` / 游戏目录根）一条不少、顺序不变，**随包那份仍然够得着**（S16）；
- `A11Y_ZDSR_DIR` 钉死搜索范围：设了就只试写的这几处（两边的空格和引号会被剪掉），
  随包的 `plugin\` 副本和默认安装目录都不再被试；两个都不可用时如实判不可用；
  清掉之后候选表恢复原样（S17）；
- 版本不匹配：第 0 份报 `InitTTS=1` 时**自动**换到随包那份并成功、安装目录那份坏掉时随包那份
  仍然够得着、所有候选都报 `1` 时如实判不可用并给出人话理由 + 试过的路径（不假装成功；
  同一份 dll 在理由里只出现一次 —— 这段是念出来的）。

最后对**真安装目录那份 dll** 做一次**只读**握手（`InitTTS` + `GetSpeakState`，不调用 `Speak`）。
报告写在仓库根的 `zdsr_selftest_report.txt`（已在 `.gitignore` 里）。

### 构建是可复现的

用仓库自带的头文件、按上面的脚本构建（0.2.0.0 实测：`git clone` 到干净目录后直接 `build\build.cmd`，再与另一个干净目录的构建逐字节对比）：

| 指标 | 结果 |
|---|---|
| 文件大小 | **完全一致（213,504 字节）** |
| `.text` / `.data` / `.fptable` / `.reloc` | **逐字节相同** |
| 全文件差异 | **4 字节**：PE 时间戳（构建时刻）在 PE 头与 `.rdata` 里各 2 字节 |

那 4 个字节是链接器写进去的**构建时刻**，不是代码 —— 也就是说，
落在磁盘上的**代码**是一样的，差异只来自「什么时候编的」。

（这个结论是**实测**的：干净克隆与另一个干净目录各编一遍，
再按 PE 节区逐段做 SHA-256 对比得到，不是从经验推断的。）

### 模组做了什么

1. **进程内插件，不是伴随程序。** 最早试过宿主进程 + 管道 + 伴随窗口：
   要跨进程抢焦点，读屏软件念的是伴随窗口而不是游戏，操作永远和游戏对不上。
   改成游戏自己加载的 V2Link 插件后，文字从游戏进程内直接交给读屏 DLL，
   没有第二份焦点、第二个窗口。
2. **语音后端链**：`Tolk`（若游戏目录有 `tolk.dll`）→ `nvdaControllerClient.dll`
   → 争渡读屏 `ZDSRAPI.dll` → `SAPI5`（纯 vtable 调用）。任一级失败都只降级，绝不把异常抛回游戏主循环。
   `Alt+Shift+F9` 可在**当前可用**的后端之间循环切换，选择记在 `plugin\a11y_speech.ini`。
3. **控件发现**：对 1920x1080 打 40px 网格，逐点问 `kag.getPrimaryLayerAt(x,y)`，
   再枚举子层、按父容器矩形裁剪、按名字与矩形去重。
4. **标签跟着语言走**：每 0.8 秒检测一次界面语言，玩家中途反复切换也会跟上。
   工具栏那 23 个动作名直接问游戏的原生菜单栏要（那是**现成的四语文本源**）。

### 几条踩过的坑（改之前请先读）

- **本作收真键盘**：走 DirectInput / 键盘状态轮询，**不经过窗口消息**。
  `PostMessage` 送进去的键游戏看不见；在窗口过程里 `return 0` 也拦不住物理按键。
  （早期"游戏不吃键盘"的结论就是用 `PostMessage` 测出来的，是错的。）
- **绝不要对这类 TJS 对象用 `for-in`**：会把整个脚本打死，而且 `catch` 不住。
  只能按索引访问 + 逐个属性 `try/catch`。
- **`new Array("a","b")` 带参数会终止脚本**，空参没事。
- **扫描结果必须按浮点解析**：控件中心的宽高可能是 `167.5` 这种半像素值，
  用 `%d` 读到 `.` 就整段中止 —— 后果是激活时点到 `(x, 0)`，屏幕最顶端。
- **拆字段时必须先把制表符打成字符串结尾**（`*tab = 0;`），
  否则层名会连父层名一起带走，噪声过滤规则一命中就把**所有**项都丢掉。
- **靠位置索引的话术表，加条目时 enum 与表行必须同顺序**：
  编译器不会报错，只会在界面上念出没被替换的 `%d`。

## 如何复现分析

补丁的每一条结论都来自两类证据之一：**运行时探针**，或**对游戏自带文本出口的读取**。

1. **运行时探针**：补丁里有一段开发用的 REPL 通道 —— 把一段 TJS 写入约定路径，
   游戏进程内的插件读进去执行，把结果写回另一个文件。
   《千恋＊万花》几乎所有"游戏里到底发生了什么"的结论（层名、控件矩形、存档 API、
   历史记录字段）都出自它。发布构建里这段通道**在编译期就不存在**（`A11Y_DEV` 开关；
   发行 DLL 字符串里查不到 `a11yb` / `sba11y_cmd`）。
2. **游戏自带的文本出口**：能问游戏要的就问游戏要 ——
   原生菜单栏 caption（`global.kag.menu.children[i].children[j].caption`）、
   KAG 的 bookmark API（`getBookMarkPageName` / `getBookMarkDate` …）、
   `global.GetSysLangText(id)`。这样拿到的永远是正确的用词，也不用自己造。

```powershell
# 装好 VS 的 32 位环境后
build\build.cmd
```

**界面标签的取证**：游戏的界面文案是**按语言预渲染成图片**的，
没有可直接读的文本表。所以标签表是**切到目标界面语言、逐屏截图、对着控件坐标逐项抄**
出来的，`data/a11y_labels_jp.ini` / `_en.ini` / `_tw.ini` 三份都是这么产生的。
**不做简繁自动转换** —— 实测转换会错（这作繁体写「遊戲設置1」「鼠標」「單擊」，
转换给不出这些词）。
