# SenrenBankaForAccessibility

本仓库是**专门针对 Steam 游戏《千恋＊万花》（Senren＊Banka，AppID 1144400）** 的屏幕阅读器
辅助补丁 —— 一个游戏内 **krkrz / 吉里吉里 Z 的 V2Link 插件**（`a11y.dll`），
文字直接交给读屏 DLL（Tolk / NVDA Controller Client / Windows SAPI），
界面用键盘导航，通过向游戏自己的派发发真实鼠标点击来实现。

- 当前版本：**0.1.0.1**（见 `CHANGELOG.md`）

## 说明

本补丁的作用：让使用读屏软件的玩家，也能基本正常地游玩《千恋＊万花》。

- 游戏里的控件**不是 Win32 控件，是 KAG 的图层** —— 对读屏软件来说整个窗口是一片空白。
  补丁自己在窗口过程里接管按键，把「按一下」翻译成对目标图层的**真实鼠标点击**
  （走游戏自己的派发），所以**不需要读屏软件做任何特殊适配**。
- 朗读剧情：说话人 + 台词。**有配音的台词不再叠一层 TTS**（人声已经在读了），
  但按 `Backspace` 仍能把这一句念出来。
- 朗读选项，并用数字键 `1`–`9` 选择（用的是**游戏自己给的按钮矩形**，不是猜的坐标）。
- 界面控件可用方向键浏览、`Enter` 激活。
- 界面标签跟着**游戏的界面语言**走（游戏有三套语言设置：主要语言、字幕语言、界面语言，
  控件跟的是第三套）。

**平台**：Windows x86。游戏是 32 位进程，所以补丁和 `nvdaControllerClient.dll` 都必须是 32 位。

## 安装（仅限正版玩家）

游戏**不会自动加载 `.tpm`**，本作是靠启动脚本里的一句 `Plugins.link("a11y.dll")` 拉起来的，
所以安装需要把一个启动槽位替换掉（原理见 `docs/DESIGN.md`）。把产物放进游戏的 `plugin\` 目录：

```
<游戏目录>\plugin\a11y.dll
<游戏目录>\plugin\nvdaControllerClient.dll     ← NV Access 官方 x86 版，需自行获取
<游戏目录>\plugin\a11y_labels.ini              ← 可选，覆盖内置标签表
```

`tools\install_when_closed.ps1` 是个省事的小脚本：等游戏退出（DLL 被占用时换不了），
换掉文件，再重新启动。

**还原**：补丁不改动游戏本体逻辑，还原就是删掉上面三个文件、恢复启动脚本。
完整步骤见 `docs/RESTORE.md`。

| 键 | 作用 |
|---|---|
| `Tab` | 进入 / 退出导航模式 |
| `↑` `↓` | 选择控件（念出名称与 `i / N`） |
| `Home` / `End` | 首项 / 末项 |

游戏本体的原生键位（空格/回车推进、`R` 开历史、按住 `Ctrl` 快进）**不动**，补丁不去抢占。

## 构建

只需要一样外部东西：Visual Studio 的 32 位命令行环境。
编译所需的 TJS2 接口头文件**已经随仓库提供**（`third_party\tjs2`，见 `third_party\README.md`）。

```cmd
set VCVARS="C:\Program Files\Microsoft Visual Studio\...\VC\Auxiliary\Build\vcvars32.bat"
build\build.cmd
```

产物是 `a11y.dll`（导出 `V2Link` / `V2Unlink` / `GetModuleThreadModel`）。
想改用自己的一份头文件，设 `TJS_INC` 覆盖即可。

### 构建是可复现的

用仓库自带的头文件、按上面的脚本构建，产物与作者的构建结果：

| 指标 | 结果 |
|---|---|
| 文件大小 | **完全一致（205,312 字节）** |
| `.text` 代码段 | **逐字节相同** |
| 全文件差异 | **4 字节**，全部落在 `.rdata` |
| `.data` / `.fptable` / `.reloc` | 逐字节相同 |

那 4 个字节是 PE 时间戳与调试目录里的构建路径 —— 也就是说，
落在磁盘上的**代码**是一样的，差异只来自「什么时候、在哪个路径编的」。

（这个结论是**实测**的：把仓库里的 `src/` 用同一套开关重新编一遍，
再按 PE 节区逐段做 SHA-256 对比得到，不是从经验推断的。）

### 模组做了什么

1. **进程内插件，不是伴随程序。** 最早试过宿主进程 + 管道 + 伴随窗口：
   要跨进程抢焦点，读屏软件念的是伴随窗口而不是游戏，操作永远和游戏对不上。
   改成游戏自己加载的 V2Link 插件后，文字从游戏进程内直接交给读屏 DLL，
   没有第二份焦点、第二个窗口。
2. **语音后端链**：`Tolk`（若游戏目录有 `tolk.dll`）→ `nvdaControllerClient.dll`
   → `SAPI5`（纯 vtable 调用）。任一级失败都只降级，绝不把异常抛回游戏主循环。
3. **控件发现**：对 1920x1080 打 40px 网格，逐点问 `kag.getPrimaryLayerAt(x,y)`，
   再枚举子层、按父容器矩形裁剪、按名字与矩形去重。
4. **标签跟着语言走**：每 0.8 秒检测一次界面语言，玩家中途反复切换也会跟上。
   工具栏那 23 个动作名直接问游戏的原生菜单栏要（那是**现成的四语文本源**）。

### 几条踩过的坑（改之前请先读）

- **本作收真键盘**：走 DirectInput / 键盘状态轮询，**不经过窗口消息**。
  `PostMessage` 送进去的键游戏看不见；在窗口过程里 `return 0` 也拦不住物理按键。
  （早期"游戏不吃键盘"的结论就是用 `PostMessage` 测出来的，是错的。）
- **绝不要对这类 TJS 对象用 `for-in`**：会把整个脚本打死，而且 `catch` 不住。
  只能按索引访问 + 逐个属性 `try/catch`。
- **`new Array("a","b")` 带参数会终止脚本**，空参没事。
- **扫描结果必须按浮点解析**：控件中心的宽高可能是 `167.5` 这种半像素值，
  用 `%d` 读到 `.` 就整段中止 —— 后果是激活时点到 `(x, 0)`，屏幕最顶端。
- **拆字段时必须先把制表符打成字符串结尾**（`*tab = 0;`），
  否则层名会连父层名一起带走，噪声过滤规则一命中就把**所有**项都丢掉。
- **靠位置索引的话术表，加条目时 enum 与表行必须同顺序**：
  编译器不会报错，只会在界面上念出没被替换的 `%d`。

## 如何复现分析

补丁的每一条结论都来自两类证据之一：**运行时探针**，或**对游戏自带文本出口的读取**。

1. **运行时探针**：补丁里有一段开发用的 REPL 通道 —— 把一段 TJS 写入约定路径，
   游戏进程内的插件读进去执行，把结果写回另一个文件。
   《千恋＊万花》几乎所有"游戏里到底发生了什么"的结论（层名、控件矩形、存档 API、
   历史记录字段）都出自它。发布构建里这段通道是关掉的。
2. **游戏自带的文本出口**：能问游戏要的就问游戏要 ——
   原生菜单栏 caption（`global.kag.menu.children[i].children[j].caption`）、
   KAG 的 bookmark API（`getBookMarkPageName` / `getBookMarkDate` …）、
   `global.GetSysLangText(id)`。这样拿到的永远是正确的用词，也不用自己造。

```powershell
# 装好 VS 的 32 位环境后
build\build.cmd
```

**界面标签的取证**：游戏的界面文案是**按语言预渲染成图片**的，
没有可直接读的文本表。所以标签表是**切到目标界面语言、逐屏截图、对着控件坐标逐项抄**
出来的，`data/a11y_labels_jp.ini` / `_en.ini` / `_tw.ini` 三份都是这么产生的。
**不做简繁自动转换** —— 实测转换会错（这作繁体写「遊戲設置1」「鼠標」「單擊」，
转换给不出这些词）。

## 内容边界

本仓库严格遵守一条线：**任何会影响开发商与发行商利益的内容都不入库**。

**入库的**：

- 补丁自己的源码、构建脚本、文档；
- `data/a11y_labels*.ini` —— **控件的功能性名称**（形如 `topmost_on=总在最前：开`）。
  这些是界面上给玩家看的控件标签，用途是让读屏念出正确用词，而不是层名；
  其中包含角色语音选择界面的角色名（**那是可选项的文字，不写就没法选**），
  不包含任何剧情内容；
- **引擎的**接口头文件 `third_party/tjs2/`（见下）。

**不入库的**（`.gitignore` 里逐类拉黑，误敲 `git add .` 也拦得住）：

- 游戏本体与资源：`*.xp3` `*.sig` `*.exe` `*.dll` `savedata/` …
- 游戏脚本 / 剧情：`*.ks` `*.scn` `*.psb` `*.tjs` `*.func` …
- 音视频与图片：`*.ogg` `*.png` `*.pimg` …、`shots/`
- **逆向与解包分析脚本、反汇编产物**：XP3 解包、脚本解密、TJS 反汇编、探针转储目录 …
- 运行日志与探针输出（可能夹带剧情文本）

日常诊断日志写在游戏目录外的本地路径，不进仓库。

### 做了什么、没做什么

说清楚，免得读者误会：

- **做了**：在正版游戏上跑运行时探针，观察游戏自己的对象与字段；
  读取游戏**本来就以明文存在**的脚本文件来理解界面结构；
  切界面语言 + 逐屏截图，把界面上的文字抄成标签表。
- **没做**：没有破解任何加密 —— 游戏有一部分资源是加密的，
  解出来是乱码，我们**没能读、也没有实现任何解密**，那部分信息一律靠截图取证；
  没有修改、替换或再分发任何游戏文件；没有绕过任何技术保护措施；
  没有把任何剧情文本带进本仓库。
