# 无障碍补丁流水线

> 从三个已发布仓库（BelfryForAccessibility / TheNOexistenceNForAccessibility / TransparentHerForAccessibility）
> 逆向出的可复用工程规范，并用第 4–10 作（aliya / justlilith / manosaba / MeiKong /
> SenrenBanka / OurBriefEternity / SisterOtherParanoia）的实战校正。
>
> **用途**：下一个补丁（第十一作）从第 0 天起按本文档执行，目标是把平台层从「重写」变成「拷贝」，
> 把工期集中到真正逐作不同的两件事：**文本清洗** 与 **补丁点挂载**。
> 但先读 §3 与 §3.6：**先判路线 + 先判交互形态**——只有 Unity 作品能整份拷贝平台层；
> 非 Unity 作品只继承契约与纪律；而所有作品都必须先定交互形态 A/B/C（§0.5、§3.6），
> 否则做出来的东西「像外挂」，而不是「像游戏本身就有这个无障碍」。
>
> 证据基础：三个源仓库 `main` 分支完整克隆（HEAD 2026-09-14），SHA256 逐文件比对 + 逐行 diff；
> 第 4–7 作的逐作细节与证据在 [`实践仓库经验-第4至7作.md`](实践仓库经验-第4至7作.md)，
> 第 8–10 作（跨引擎路线）在 [`实践仓库经验-第8至10作.md`](实践仓库经验-第8至10作.md)。

## 0. 结论先行

### 0.1 三作的共同点（一句话）

**它们是同一套代码的三次「复制—改名—局部改写」，而不是三个独立项目。**

- 平台层（语音朗读 + 界面导航）三作几乎逐字节相同，差异只有 `namespace` 一行；
- 逐作真正改写的只有 **文本清洗规则** 和 **Harmony 补丁点**；
- 三作共用同一套构建 / 探针 / 打包 / 合规 / 文档骨架；
- 因此**共性不是「设计得像」，而是「事实上就是同一份」** —— 可以直接固化成模板。

### 0.2 最关键的三个数字

| 指标 | 数值 | 含义 |
|---|---|---|
| 平台层规模 | **约 2130–2390 行**（Speech + Sapi + Nvda + UiNav） | 这部分可以整份复用，不重写 |
| `Sapi.cs` / `Nvda.cs` / `Speech.cs` 三作差异 | **0 / 1 / 3–10 行**（前两者的差异只有 `namespace`） | 已是事实上的冻结层 |
| `Plugin.<成员>` 跨文件引用 | **63 / 117 / 64 处**，散在 4–9 个文件 | ABI 未固化，是复用的唯一真实摩擦 |

### 0.3 本流水线的核心主张

> **把平台层与逐作代码之间的接口（ABI）固化成一层显式的 `A11yHost` 契约。
> 契约一旦固化，平台层逐字节复用；不固化，每作都要重做 63–117 处改名 + 人工回归。**

这是本文档唯一要求「新增设计」的地方，其余全部是既有实践的固化。

### 0.4 第 4–10 作校正了什么（相对三源）

- **平台层从「三份副本」变成「框架 + 逐作冻结副本」**：第 6 作（manosaba）与 Framework 0.2.4.0
  仅 1 个文件、5 行差异；第 4 作自研了 UI Toolkit 导航（`VeNav`）、第 7 作停在 0.1.1.0。
  → 「平台会漂移」从隐患变成事实，新增 §6.5（逐作升级 8 步）与 G33（逐 tag 哈希）
- **新界面技术栈**：第 4 作完全没有 uGUI `Selectable`，旧 `UiNav` 整套失效。
  → 新增 §3.1（技术栈判别）与 §3.2（三种 L3 补法：虚拟控件桥 / 临时编号菜单 / 只读扫描）
- **新失败模式**：补丁挂载 ≠ 命中、合成输入 ≠ 真实输入、等待输入态是禁区、
  IL2CPP 进程外测不了 → 新增 I4–I6 与 §5.4 的 G13–G36
- **工具链第一次被真实使用**：骨架生成器漏 `GlobalKeys.cs`、不生成 `Choices.cs`、
  Plugin 模板只有 Mono、build/release 只有 BepInEx 5 → 本次一并修模板与 `compile_check`
- **第 8 作（KiriKiri Z）打掉「引擎会加载插件」的前提**：没有 BepInEx、没有 `plugins\`，
  唯一入口是改游戏归档 → 新增 §3.3 第四条路线 + §5.5 的 G37–G45（改归档验收、32 位双保险、
  安装器可重建、开发通道编译期关闭）
- **第 9 作（Ren'Py）打掉「引擎是 C#/Unity」的前提**：脚本运行时本身就是 API，
  但钩子存在 ≠ 被调用、时序错一拍就静默失效 → 新增 §3.4 第五条路线 + §5.6 的 G46–G55
- **第 10 作（NVDA 双进程）打掉「换宿主也算 L3」的误解**：L1 完全不可复用、
  违反 Repeat-only 纪律 → 新增 §3.5 对照路线（明确否决），只吸收 §5.7 的测试方法论
- **结论升级**：共性仍是「同一份代码在复制」，但复制必须靠**清单 + 生成器 + 静态守卫**，
  只靠口头纪律必然漏文件；且**框架边界要写清**：L1 只服务 Unity，契约与纪律才跨引擎

### 0.5 第 0 条纪律：交互形态（0.2.7.0 起）

> **原话**（用户转述的指点）：**「你不要把 mod 写得跟外挂是的，要写得像游戏本身就有这个无障碍一样。」**
> 这是**第 0 条纪律**，优先级高于本文其余全部规则；权威全文见
> [`交互形态纪律.md`](交互形态纪律.md)。本节只做摘要与落点，措辞冲突时以该文为准。

用户给了三条解读，本文把它们当成三句判据：

1. **优先采用游戏自己的完全键盘控制接口，与游戏函数交互** —— 按键要落在游戏自己的输入 / 键位 / 焦点机制上；
2. **游戏没有完全键盘控制，就手动制造或补全它** —— 但补出来的仍走游戏自己的那条路，不是另造一套；
3. **不要加入「导航模式」这类像外挂的东西** —— 没有补丁专属的元操作，不需要玩家先按某个键「进入操作状态」。

由此得到 **A / B / C 三条路线**（P0 必选其一，写进逐作 `docs/交互形态判定.md`）：

| 路线 | 判定 | 做法 |
|---|---|---|
| **A** | 游戏已有完全键盘控制（全流程、逐界面、不依赖鼠标） | 补丁**只朗读**，不碰输入、焦点、键位 |
| **B** | 有键盘但不完全（某些界面只能鼠标 / 焦点不可见） | 在游戏自己的输入 / 焦点层补全缺失的键或动作，**无模式开关** |
| **C** | 没有键盘控制 / 没有控件模型 | 调游戏自己的动作函数制造完全键盘控制，入口仍是游戏的一部分；**无模式开关** |

**本文其余章节与第 0 条冲突时，以第 0 条为准**：例如 §6 P7 旧快捷键表里的
「`Tab` 进入 / 退出界面导航模式」是 0.2.x 的**遗留形态**，只对老作成立，新作默认不得出现；
§2.1 的 `UiNav` 导航引擎同理 —— 保留是为老作逐字节不变，不是推荐方案（§3.6、§5.8）。

## 2. 架构：三层

```
┌──────────────────────────────────────────────────────────┐
│ L1 平台层（逐字节复用，永不逐作改写）                      │
│   Speech.cs  后端链 Tolk→NVDA→争渡→SAPI + 定期重试        │
│   Nvda.cs    nvdaControllerClient.dll 探测与朗读          │
│   Zdsr.cs    争渡读屏 ZDSRAPI（运行时按目录加载）          │
│   Sapi.cs    纯 P/Invoke + vtable 的 ISpVoice             │
│   UiNav.cs   Unity Selectable 通用导航引擎                │
│   Hotkey.cs  组合键解析（修饰键严格匹配 + 主键必需）      │
│   KeyEdge.cs 单键边沿 + 局部/全局并集 + 松开闩锁          │
│   GlobalKeys.cs 整机 Win32 按键读取 + 焦点门（0.2.3）      │
│   Repeat.cs  重读缓冲区（唯一允许更新重读内容的地方）      │
├──────────────────────────────────────────────────────────┤
│ L2 契约层（每作一个薄适配文件，固化 ABI）                  │
│   A11yHost.cs  共享层唯一可见的宿主（配置 + 日志 + 钩子）  │
│   Plugin.cs    BepInEx 入口：注册配置、注册补丁             │
├──────────────────────────────────────────────────────────┤
│ L3 逐作层（真正的开发工作量所在）                          │
│   TextProc.cs     原始文本 → 可朗读文本（本作专属规则）    │
│   Patches/*.cs    Harmony 补丁点（按反编译实查的方法名）   │
│   Choices/Qte/…   本作特有的交互形态                      │
└──────────────────────────────────────────────────────────┘
```

### 2.1 L1 平台层的复用边界（精确到成员）

**`Speech.cs`** — 语音输出抽象层。

```
公开接口（全部静态）：
  Backend Current                 当前后端枚举 None/Tolk/Nvda/Zdsr/Sapi
  string  BackendName             可朗读的后端名（含 Tolk 探测到的读屏名）
  bool    TolkHasBraille          盲文可用性
  void    Init(ManualLogSource)   按优先级挑选第一个可用后端
  bool    Ready()                 不可用时每 10s 重试（NVDA 可能后启动）
  void    Speak(string, bool)     朗读；interrupt 决定是否打断
  string  CycleAvailable()        运行中切到下一个可用后端（0.2.0.0），返回播报文本
  void    Stop()                  停止
  void    Shutdown()              Tolk_Unload + Sapi.Shutdown
```

关键设计（**照抄，不要重新发明**）：

- **每作必须绑「切换语音后端按键」**（默认 `Alt+Shift+F9`，配置名 `切换语音后端按键`）：
  `Speech.CycleAvailable()` 只负责「切到下一个可用后端 + 返回播报文本」，**按键注册在逐作层**
  （平台层不知道逐作配置，也不读键）。按下后用 `Hotkey.Down(spec)` 判边沿，把返回值经
  `Repeat.Say` 念出（**不要 `Speech.Speak`**：逐作层直连 Speech 会绕过重读缓冲区，`lint_repeat.ps1` 拦）。
  这是玩家在游戏内**唯一的后端自救手段**（读屏中途退出/后启动/探测失败），不能省。
- 自带 NVDA / 争渡 / SAPI 三级，**不强依赖 Tolk**（维护分支 `ndarilek/tolk` 有 CI 构建的 `tolk.zip`，但无版本 tag、只有 `master`；
  Tolk 是 **LGPL-3.0**，随包须附许可全文。且 JAWS/SuperNova/ZoomText 分支无法验证）。
- 争渡这一级的可用性判据**只能是** `GetSpeakState() ∈ {3,4}`：未授权时 `Speak()` 也返回 0，
  拿返回值当判据就是「日志一片绿、耳朵一片安静」（0.2.0.0 的 `Zdsr.cs`）。
- 后端选择可被配置钉死（排查用）；**钉死后不可用不会回退**，这是刻意的。
- 初始化失败时把每个后端的结论串成一行日志（`Verdict()`），一眼看出「为什么全灭」。
- 朗读抛异常 → 后端降级为 `None` 并允许重试，绝不把异常抛给游戏主循环。

**`Sapi.cs`** — Windows 内置语音，**纯 P/Invoke**。

> **绝不要用** `Type.GetTypeFromProgID("SAPI.SpVoice")` + `InvokeMember`。
> Unity 的 Mono **没有实现** COM 后期绑定，实机日志是
> `SAPI 不可用: NotImplementedException`，表现是整局游戏一片安静。

已实机验证的 vtable 槽位（照抄，错一位就会当场露馅）：

```
0  QueryInterface        1  AddRef              2  Release
3  SetNotifySink         4  SetNotifyWindowMessage
7  SetNotifyWin32Event   10 SetInterest         11 GetEvents
16 Pause                 17 Resume              18 SetVoice
20 Speak                 21 SpeakStream         22 GetStatus
28 SetRate               29 GetRate             30 SetVolume
31 GetVolume             32 WaitUntilDone       33 SetSyncSpeakTimeout
```

- `CLSID_SpVoice = 96749377-3391-11d2-9ee3-00c04f797396`
- `IID_ISpVoice  = 6c44df74-72b9-4992-a1ec-ef996e0422d4`
- `COINIT_APARTMENTTHREADED = 0x2`，`CLSCTX_ALL = 0x17`
- **`SPF_ASYNC = 1` 必须置位**：SAPI 默认同步朗读，会阻塞 Unity 主线程导致游戏卡死。
- `Stop()` = `Speak(NULL, SPF_ASYNC | SPF_PURGEBEFORESPEAK)`（`SPF_PURGEBEFORESPEAK = 2`）。
- 初始化时**先读 rate/volume 验证 vtable 槽位**（错了在这一行露馅，而不是等玩家需要朗读时静默失败）。

**`UiNav.cs`** — 通用导航引擎，**几乎不引用任何游戏类型**。

> **0.2.7.0 遗留标注（第 0 条纪律，§0.5）**：下面这套「每帧扫 `Selectable` + 自排分组 +
> 按 `Tab` 进入导航模式」是 0.2.x 的**历史实现，不是合规范本**。新作默认不启用
> （`CfgMenuNav=false`，§3.6、§5.8 G61/G62），是否接入由 P0 的 A/B/C 判定决定。
> 本节保留只为说明老作平台层为什么长这样、以及逐字节复用时它在干什么。

belfry / transparenther 引用的类型只有 UnityEngine 系：

```
UnityEngine.EventSystems · UnityEngine.Object · UnityEngine.SceneManagement
UnityEngine.UI · UnityEngine.UI.Text · (TMP)
```

引擎机制（照抄）：

| 机制 | 实现 |
|---|---|
| 控件发现 | 每帧扫描 `Selectable`（**不依赖游戏提供任何列表**） |
| 分组 | 按控件在 Canvas 下的**顶层祖先**分组；组间按 `CanvasOrder → SiblingIndex` |
| 组内排序 | `ItemKey` 字典序：**Row（屏幕上下）→ Left（屏幕左右）→ Path（渲染层级）** |
| 重扫 | **只扫「下一帧」**，且加**场景稳定门禁**（`SceneStable` / `SceneSettleSeconds = 1.5f`） |
| 位置换算 | `WorldToScreenPoint` 后再分档（世界坐标 ≠ 屏幕像素） |
| 可见性 | `VisiblyClickable` + `CanvasGroup.alpha` |
| 退出确认 | `QuitConfirmArmed` / `QuitConfirmSeconds = 8f` |
| 危险操作 | `NeedsQuitConfirm` + `CfgQuitNames` |
| 输入角色 | `InputFieldRoleName` / `SliderValueText` / `PlaceholderText` |

> **绝不要对 `List.Sort` 的比较函数用「近似相等」当分支**（如 `Mathf.Abs(a.Left-b.Left) > 0.01f`）。
> 它不满足传递性，内省排序的结果是**任意的**，而且**不报错**。必须严格字典序。

**`Hotkey.cs` / `KeyEdge.cs` / `GlobalKeys.cs`** — 输入三件套（0.2.0.0 ~ 0.2.5）。

| 文件 | 职责边界 | 不能做的事 |
|---|---|---|
| `Hotkey.cs` | 把 `Ctrl+Alt+G` 这类配置字符串解析成「修饰键严格匹配 + 必须有一个主键」；`Down(spec)` 回答「这一帧是否按下」；`GlobalHeld` / `GlobalPressed` 只认委托（保证可单文件编译） | 不读 `A11yHost` 配置（留给逐作）、不做长按/连发闩锁（逐作层做）、不猜键名（解析失败必须打印原因） |
| `KeyEdge.cs` | 单键边沿：`Pressed(k)` = 局部 `Input` ∪ 全局（`UseGlobalKeys`）；**松开闩锁**（合成输入重复 `GetKeyDown` 只算一次）；`ModifierChordDown` 组合键状态机 | 不解析带修饰键的配置串（那是 `Hotkey`）、不直接读 `GlobalKeys` 以外的东西 |
| `GlobalKeys.cs` | 整机范围 `GetAsyncKeyState` 读取 + 边沿表 + 组合键快照；`Reading` 由 `A11yHost.UseGlobalKeys` 懒同步；0.2.5 起再过 `A11yHost.KeyInputAllowed` 焦点门 | 不装全局钩子、不做 DLL 注入；门关掉时**清边沿表**（否则重开门会把关门期间的按住当成新的按下沿） |

> 键名映射的坑：`Enum.TryParse("=")` **不认**这个符号（0.2.5 必修：显式映射到 `KeyCode.Equals`）；
> `Enum.TryParse("0")` 成功但得到 `KeyCode.None`（G3）；未知键静默返回 false → 解析结果必须落日志（G32）。

**`Repeat.cs`** — 重读缓冲区，0.1.1.0 起进 L1（第 7 作《妹控计划》升级时再次暴露 `Push` 语义漂移）。

- 逐作层的朗读**只能**走 `Repeat.Say` / `Note` / `Push`，不许直接 `Speech.Speak(`（`tools/lint_repeat.ps1` 机械断言）。
- `Push(text, tag)` 的冻结语义是 **「进缓冲区 + 自己播报」**；只记不念用 `Note`。
  第 7 作的本地副本语义相反（只记不念），升级时直接替换会双播 —— 见 §5.4 G33 与 §6.5。
- 重读是玩家主动请求：直接走 `Speech`，**不经过去重与排队**。
- **有配音的行只记不念**：判定为「有配音」的台词一律 Note —— 进重读缓冲区、**不自动播报**；
  自动朗读只覆盖无配音行。语音已经在播，再 Say 一遍就是叠音；反过来漏了 Note，
  读屏用户就**永远听不到这句台词**（唯一的朗读通路是重读键）。两种情况都在实机里踩过。

### 2.2 L2 契约层：固化 ABI（**本流水线唯一的新增设计**）

**问题**：共享层目前直接读 `Plugin.xxx`，导致三作命名漂移、每作要改 63–117 处。

**方案**：新增 `A11yHost.cs`，作为**共享层唯一允许引用的宿主**。

```csharp
// A11yHost.cs —— 每作一份，只填值，不写逻辑
internal static class A11yHost
{
    // ---- 日志（共享层唯一日志出口）----
    internal static ManualLogSource Log;
    internal static bool DiagOn;                 // 「界面诊断日志」总开关
    internal static void Diag(string msg) {      // 统一诊断出口，带 [UiNav]/[朗读] 前缀
        if (!DiagOn || Log == null) return;
        try { Log.LogInfo(msg); } catch { }
    }

    // ---- 共享层需要的配置（名字固定，语义固定）----
    internal static ConfigEntry<string> CfgSpeechBackend;   // 自动/Tolk/NVDA/争渡/SAPI
    internal static ConfigEntry<bool>   CfgDiagLog;         // 朗读诊断日志
    internal static ConfigEntry<bool>   CfgVisibleOnly;     // 导航只含可见控件
    internal static ConfigEntry<bool>   CfgSortByPosition;  // 按屏幕位置排序
    internal static ConfigEntry<string> CfgExcludeNames;    // 人工排除名单（逗号分隔）
    internal static ConfigEntry<bool>   CfgQuitConfirm;     // 退出二次确认
    internal static ConfigEntry<string> CfgQuitNames;       // 需确认的控件名

    // ---- 共享层需要的钩子（由各作 Plugin/Patches 实现）----
    internal static Func<bool> BlockGameAdvance;  // 导航模式下是否拦截「推进剧情」
    internal static Action      TickUiNav;        // Plugin.Update 每帧调用（含 KeepUnitySubmitOff）

    // ---- 只增不改的扩展钩子（0.2.2 ~ 0.2.5；留空 = 旧行为）----
    internal static Func<bool> ShouldMuteUnitySubmit; // 这一下回车/空格是否由导航接管
    internal static Func<bool> NavTogglePressed;      // 本作导航开关键（默认退回 Tab）
    internal static bool UseGlobalKeys;               // 用 Win32 全局读取补足 Input
    internal static Func<bool> KeyInputAllowed;       // 全局读键焦点门（null = 不设门）
}
```

> **契约只增不改**：0.2.2 之后每个新钩子都必须满足「留空 = 旧行为逐字节不变」。
> 现在已有 4 个这样的钩子；新增时同步在 `Clear()` 里复位，并在模板注释写清
> 「谁调用、什么时候调用、异常怎么兜底」。

**迁移成本（已实测）**：只需把共享层里的
`Plugin.Log` / `Plugin.CfgXxx` / `Plugin.Diag` 改指 `A11yHost.*`，
并让各作 `Plugin.cs` 在 `Awake/Load` 里填一次值。三作合计 244 处引用、19 个文件要过一遍，
但**这是最后一次**：之后新作只需照抄 `A11yHost.cs` 填空。

**共享层绝不允许引用的东西**（一旦引用就丧失复用性）：

- 任何游戏类型（`DialogueScene` / `Naninovel.*` / `PhoneDialogueManager` …）
- 任何逐作配置项（`CfgReadUnvoiced` / `CfgSilenceKey` / `CfgChoiceHotkeys` …）
- `Il2CppInterop` / `Il2CppSystem`（IL2CPP 路线的特化处理留在逐作层）

## 3. 第一条硬约束：选技术栈路线

**这是新作的第 0 个决策，决定后续一切。**

> **0.2.7.0 补注**：开新作现在是**两个第 0 决策** —— **技术栈路线**（本节）
> + **交互形态判定**（§3.6）。前者决定「怎么编译、怎么安装」，后者决定「做出来像不像
> 游戏本身的一部分」；两个都在 P0 定完，未定完不得进 P2。

| | **Mono 路线** | **IL2CPP 路线** |
|---|---|---|
| 参考实现 | TransparentHer（v0.5.9.0）、belfry | noexistence |
| BepInEx | **5.4.23.5** | **6.0.0-be.788** |
| 插件入口 | `BaseUnityPlugin` | `BasePlugin` |
| TFM | `netstandard2.1` | `net6.0` |
| 引用来源 | `<游戏目录>\<Game>_Data\Managed\*.dll` | `<游戏目录>\BepInEx\interop\*.dll` |
| 参考 BepInEx 程序集 | `bep_dl\BepInEx\core\BepInEx.dll`（构建脚本自下） | `<GameDir>\BepInEx\core\BepInEx.Core.dll` 等 |
| 前置条件 | 无（直接读 Managed） | **必须先装 BepInEx 6 并跑一次游戏**，生成 `BepInEx\interop\` |
| 额外配置 | — | `AllowUnsafeBlocks` + `<CodePage>65001</CodePage>` + 可能需要打过补丁的 `Il2CppInterop.Runtime.dll`（上游 PR #277） |
| 危险点 | 较少 | **三类「静默失败」**，见 §4.2 |

**判定方法**：看游戏目录里是 `<Game>_Data\Managed\Assembly-CSharp.dll`（Mono）
还是 `<Game>_Data\il2cpp_data` + `GameAssembly.dll`（IL2CPP）。

> 两作 Mono 的 csproj 都**必须**有可复现构建三行：
> `<Deterministic>true</Deterministic>` +
> `<IncludeSourceRevisionInInformationalVersion>false</IncludeSourceRevisionInInformationalVersion>` +
> `<EnableSourceLink>false</EnableSourceLink>`
> **只关前两条是不够的**：SDK 默认 `EnableSourceLink=true`，会把当前 git 提交写进 PDB，
> PDB 的内容哈希又进 DLL 的 debug 目录与确定性 MVID。TransparentHer 就只关了第一条、
> 以为修好了，一提交才发现产物还是变。

### 3.1 分支三：界面技术栈（uGUI / UI Toolkit / 无控件）

> 它不是宿主路线，但决定 L3 用哪种补法；宿主路线见 §3.3 / §3.4。

选完 Mono/IL2CPP 只决定了**怎么编译**；界面是什么技术，决定了**导航能不能复用**。
第 4 作《彼方的她》给出了反例：Unity 6 Mono，但界面全是 **UI Toolkit**，一个 `Selectable`
都没有 —— `platform/UiNav.cs` 的两条根基（扫 `Selectable`、按 Canvas 分组）同时失效，
导航不是「怎么点」而是「控件在哪里」，只能另写一套。

| 界面技术 | 判别（P1 探针） | 导航路线 | 平台层处置 |
|---|---|---|---|
| **uGUI** | 场景树里有 `Selectable`（Button/Toggle/Slider…）与 `EventSystem` | `UiNav` 直接可用 | 不动 |
| **UI Toolkit** | 有 `UIDocument` / `VisualElement` 根；`Selectable` 数量为 0 | 另写 `VeNav`：`VisualElement` 枚举、`resolvedStyle` 判可见、反射 `Clickable.clicked` 激活 | `UiNav` **不要**改成双后端；UI Toolkit 后端先作为**逐作模板**存在，稳定后再谈 L1 |
| **无控件（全绘制）** | 探针扫不到可交互对象，只有一张大图/自定义输入 | 走「游戏状态跳转 + 临时编号菜单」，**不硬做逐控件导航** | 不动 |

UI Toolkit 的六条硬约束（照抄，不要重新发现）：

1. **「隐藏」有两套写法**：内联 `style.display = None` 与样式表 `.hidden{display:none}`。
   只查 `style.display` 会读到 `Null`，把关着的面板当可见 → 必须查 `resolvedStyle.display`。
2. **可见性四道判据**：panel 非空 + 祖先链无隐藏（逐级 `parent`）+ `resolvedStyle.visibility != Hidden`
   + `resolvedStyle.opacity > 0.01` + `worldBound` 宽高 ≥ 1。
3. **点击不要走 `Button.clicked` / `SimulateSingleClick` / `NavigationSubmitEvent`**：
   前者只是转发；`SimulateSingleClick` 是 `internal`；`NavigationSubmitEvent.target` 不可写。
   可行路径是反射 `Clickable` 的私有委托字段后 `Invoke()`（等同真人点一下，游戏自己的音效/置灰/高亮都会走）。
4. **「没接线」要与「点失败」区分**：读同一个私有字段判定 `HasClickHandler`，失败时回退业务确认委托。
5. **命中控件后不递归进子树**：UI Toolkit 里 `Label` 在子节点上是常态，递归必然重复播报。
6. **「控件 → 标签」要自己找**：设置滑条没有 `label`，标签是排在它前面的独立 `Label`
   （可能在别的容器）。三级回退：同父里控件之前的最后一段文本 → 往上 1–3 级祖先同样找 → 父节点子树第一段文本。

### 3.2 没有 Selectable 时的三种补法（都是 L3，不是 L1）

| 补法 | 做法 | 适用 | 代价/风险 |
|---|---|---|---|
| **虚拟控件桥** | 给非 Selectable 的世界对象自建 `Canvas` + 全透明 `Button`（`Image.alpha = 0` 但 `raycastTarget = true`）+ `GraphicRaycaster` + 高 `sortingOrder`（如 32000），点击走游戏原生链路；用中间容器保住组名〔justlilith 实机〕 | 3D 场景里的可点物体、身体部位、地图热点 | 与游戏自己的 UI 层级/射线竞争；`CanvasGroup.alpha` 必须保持 1，只让 Image 透明 |
| **临时编号菜单** | 只列「此刻找得到的入口」，念编号，数字键派发，10 秒有效窗口〔MeiKong 实机〕 | 入口散落在游戏各处、没有统一面板 | 玩家要记编号；菜单必须能随时重新呼出 |
| **只读扫描** | 每 0.22s 扫可见 `TMP_Text`，去重后播报浮字/字幕〔justlilith 实机〕 | 没有事件可挂的浮动提示 | 只读、不建表、不持引用、不激活；与 G11 的边界是「只读不碰生命周期」 |

另两条通用范式：

- **先叫出游戏菜单**：平台只扫「可见」控件，游戏默认不显示功能菜单时导航空转。
  逐作要给一个「呼出功能菜单」的入口（热键），并做 **keepalive 四道闸**：
  仅补丁期间、对话即停、N 秒无焦点收起、冷却/次数上限/连续熔断。
- **感知缺口要如实说**：全程配音的作品，`Reader` 用 voiced/unknown 三态决定「默认不自动朗读」；
  图像消息无法朗读时，文档里写清楚，不要假装覆盖。

### 3.3 第四条路线：引擎根本没有插件宿主（KiriKiri Z / 原生 `V2Link`）

第 8 作《千恋＊万花》把 Framework 的第五个隐含前提打掉了：**不是所有视觉小说都有
「插件宿主 + 解压即安装」**。它是 KiriKiri Z（吉里吉里），游戏目录里没有
`<Game>_Data\Managed`，也没有 `il2cpp_data`；PE32、版本资源
`ProductName=TVP(KIRIKIRI) Z core` / `FileVersion=1.2.0.3`。

| 维度 | 这条路线的事实 |
|---|---|
| **挂接契约** | 引擎认三个导出：`V2Link` / `V2Unlink` / `GetModuleThreadModel`。取引擎函数走 `iTVPFunctionExporter` 虚表**下标 1** `QueryFunctionsByNarrowString`，按**完整签名**匹配 5 个函数：`TVPGetScriptDispatch` / `TVPExecuteExpression` / `TVPExecuteScript` / `TJSAllocVariantString` / `TVPDoTryBlock` |
| **失败隔离** | 每次调用先判 `g_getScriptDispatch() == NULL` 直接返回；所有脚本交互包在宿主自己的 `TVPDoTryBlock` 里，异常文本写日志、**绝不外抛回游戏主循环** |
| **部署通道** | **引擎不自动加载 `plugin\*.dll`**。13 种非破坏性外挂思路全部失败（散装脚本、自建 `a11y.xp3`、`patch0/1/x.xp3`、字节码/明文…）；唯一可执行点是把游戏自己的启动脚本槽位改掉 → **必须改游戏归档**（反向证据：`patch.xp3` 里的官方脚本确实生效） |
| **改归档纪律** | 内层索引**逐字节照抄**。按 adlr 哈希重建会**静默丢 storage**（实测丢 18 个），症状不是启动失败，而是之后剧本引用抛类型错误 |
| **验收方式** | 三向核对：条目**集合与顺序**逐项一致 + Python/C# 两套注入器产物逐字节相同 + 体积差异只来自 zlib。**「能启动」不算验收** |
| **构建** | 不用 dotnet/BepInEx：`VCVARS32` + `build.cmd`；`VSCMD_ARG_TGT_ARCH=x86` 硬失败 + `/MACHINE:X86` + 包内 PE `Machine=0x014C` 断言。x64 下「构建成功」会产出 x64 DLL，32 位游戏**静默不加载** |
| **安装/还原** | 安装 = 替换 `data.xp3`（~985 MB）+ 放 `plugin\` 文件，注入器在玩家机器上跑约 4.5 秒；**发布包不携带改好的归档**（99.95% 是游戏资源）。还原走「加法」模式；**改过归档只能从原始备份整包恢复**，不允许二次修改 |

> **L1 处置**：`platform/` 的 C# 平台层在这条路线上**完全不可复用**。
> 可复用的是**契约与纪律**：语音后端链（`Tolk → nvdaControllerClient → ZDSR → SAPI`，
> `F9` 在可用后端间循环，失败只降级）、`Zdsr` 的候选/TTL/绝对路径细节、诊断日志、
> 后端自检。它们与 `platform/Zdsr.cs` 是**同一契约的两份实现**，改一侧必须同步另一侧（§2.1）。
> 具体代码级事实见 [`实践仓库经验-第8至10作.md`](实践仓库经验-第8至10作.md) §1。

### 3.4 第五条路线：引擎是脚本运行时（Ren'Py）

第 9 作《Our Brief Eternity》（Ren'Py 8.6）走的是另一条极端：**没有 DLL 插件宿主，
但引擎脚本层本身就是完整的运行期 API**。判定特征：目录里有 `renpy\`、`game\*.rpy`/`.rpyc`、
`*.rpa`，没有 `Managed`/`il2cpp_data`。

**分层与 init 顺序**（顺序就是契约；错一拍 = 静默失效，引擎 lint 仍 exit 0）：

```
init -200  00_contract.rpy        契约（单一默认 store + 具名槽位）
init -190  90_plugin.rpy          逐作入口填 GameName / 版本 / 全部开关
init -103  05_repeat.rpy          重读缓冲区（唯一朗读出口）
init -100  01_speech.rpy          后端链
init  -60  20_textproc / 30_choice
init  -55  22_uialt.rpy           逐作文案表
init  -50  10_renpy_adapter.rpy   L2.5 引擎适配（接管 config.tts_function）
init  -45  08_uialt.rpy           焦点表 / 导航
init 1200  06_keymap.rpy          必须晚于引擎 00keymap.rpy 的 init 1100
init 1300  90_plugin.rpy          validate → 启动 → 安装键位
```

> `10_renpy_adapter` 是**新增的 L2.5 引擎适配层**：引擎适配不属于 L1，否则 L1 会引用
> 引擎私有对象，下一个 Ren'Py 作品没法整份复用。

| 维度 | 这条路线的事实 |
|---|---|
| **取对话** | `config.say_menu_text_filter`（`ast.py:971`）。`config.all_character_callbacks` 注册成功但真实 say **从不触发**——存在 ≠ 被调用（G46） |
| **取说话人** | filter 比 `store._last_say_who` 赋值（`ast.py:985`）早，直接读会拿到**上一行**的说话人；先记文本 + 标志，下一帧再补（G47）。`predict` 也会调 filter，记录与朗读必须分离 |
| **取选项/主菜单** | 覆盖 `screen choice` / `screen main_menu` 加 `alt`；声明式覆盖受加载顺序与 `init offset` 控制，注册错层整段不生效（G48） |
| **取界面** | 引擎焦点表 `renpy.display.focus.focus_list`（`focus.py:88-109`，每轮渲染重建）+ **拉模型**查表；不往控件里写（推模型 `style.alt` 注入实测不生效） |
| **键位** | `config.keymap` + `config.underlay`，登记必须 `init 1200`；`renpy.Keymap` 值**无参调用**（`behavior.py:550-565`） |
| **朗读出口** | 唯一出口 `A11yRepeat.say()`；逐作不得绕过（`lint_patch.py` 断言 C 机械拦）；自动播报排队不打断，玩家 F5 才打断 |
| **后端链** | Tolk → NVDA → 争渡 → 引擎同款 SAPI（**子进程** `wscript say.vbs`；裸 COM 直调会 `0xC0000005`）；争渡只认 `GetSpeakState()∈{3,4}` |
| **部署通道** | 松散 `.rpy` 叠加层，**不碰 `.rpa`**（`renpy/loader.py:108-109` 磁盘优先）；安装/卸载是文件级操作，可逆 |
| **验收方式** | `tools/lint_patch.py` **12 条静态断言**（BOM 规矩与 ps1 相反：`.rpy` 不许有、`.ps1` 必须有）+ `tools/check_boot.py` **八条启动正向证据**（契约打印/接管 `tts_function`/后端结论/适配层启动/重读键/按键层/导航键/无配音角色推导）；**「没报错」≠「跑起来了」**（G49） |
| **构建/发布** | 不需要编译器；发布 = 组装 zip：白名单不含 `.ps1`、条目只落 `game/` 与包根、条目分隔符 `/`、固定时间戳可复现、打包前 IP 自检 |
| **边界** | 引擎做不到的三件事（值变化不重读、滑条标签、线性导航）由 L3 补，且**注入判据必须与播报判据一致**；本作因此明确**不需要导航模式**（与 UI Toolkit 作代价差一整个模式） |

**朗读三规则**（作品事实，不是引擎事实）：

1. 无角色名 → 全文（旁白/独白）；
2. 有角色名 + 有配音 → **只报名字**，但整句必须进重读缓冲区并打断上一句；
3. 有角色名 + 无配音 → 全文。

> 判据是「有没有角色名」，**不是「有没有配音文件」**：本作旁白占 43.2%，
> 按配音文件判会漏掉整段叙事。`voice_sustain=True`、配音音量 0、
> `config.tts_voice_channels` 守卫（`tts.py:419-421`，任一 voice 通道在播就 return，
> 根本走不到 `tts_function`）都会让判断失真，必须按行自判。

**Ren'Py 专属陷阱（写代码前先看）**：

- `init python in <名字>:` 是独立 store，块内引用不到自己；`NameError` 会中断整个 init
  （连后端链都起不来），而引擎 lint 可能仍 exit 0。
- 声明式覆盖（`screen`/`tag menu`）谁生效看松散文件与归档的加载顺序 + `init offset`；
  覆盖整段失效是发生过的。
- `config.underlay` 在引擎 `init 1100` 被**整体赋值**，补丁登记必须在 `init 1200`。
- 键名必须用引擎 `compile_event` 试解析（临时 `config.developer=True`）；写错键名
  （如 `K_KP_UP`）会让游戏**起不来**。常数从引擎读：Ren'Py 8 没有 `pygame` 模块，
  `KEYDOWN=768` 不是 2。
- 引擎 `self_voicing` 的边沿标记不可预设，否则整个界面一次都不播报；强制关掉引擎自语音
  并写进玩家偏好。
- 焦点表每轮重建：`id(w)` 不能当身份；「查不到」与「值为 None」要返回**不同哨兵**，
  否则整片界面静默；四级兜底永不静默。
- 状态词 `selected` 被追加在 `_tts_all` 上（`behavior.py:1199-1205`），只筛一层 = 假修复。
- `Bar` 不是 `Button`：`_tts_all` 尾巴硬编码「栏」（`behavior.py:2664-2671`），
  名字第一来源 `value.alt`，取值接口有三种；只给 `get_selected()` 加「：当前」。
- 不抢 Backspace（`input_backspace`）；F5 先提示音再朗读（三分判别）。

> **L1 处置**：C# 平台层不可复用；但 `A11yHost` 的**语义**可以 1:1 映射成一个 Ren'Py 模块
> （配置、朗读出口、导航开关、诊断开关），因此契约文档仍然有效。逐作细节见
> [`实践仓库经验-第8至10作.md`](实践仓库经验-第8至10作.md) §2。

### 3.5 对照路线：NVDA 插件 + 游戏内进程（**结论：不进主线**）

第 10 作把「游戏内 C# 插件」与「NVDA 插件（Python）」拆成两个进程，用本地端口通信。

**不写进主流水线的理由**（不是技术不可行，是违反框架边界）：

1. 它**不是第四种 L3 补法，而是把宿主换掉了**：L1 `platform/` 完全不可复用；
2. Python 侧重写了 Repeat、优先级、历史与配置 → 同一件事两份实现，必然漂移；
3. 安装从 1 步变 2 步，且只剩 NVDA 一个后端（违背「失败只降级」）；
4. 本地协议没有握手、长度限制与认证，端口对所有本机进程开放；
5. 直接违反「逐作朗读只能走 `Repeat.Say/Note/Push`」的纪律。

**值得偷的是方法论**（与路线无关，已并入 §5.7 测试与 §5.4 G34）：

- 假对端探针：用一个假 NVDA / 假游戏端注入固定事件，**不需要真读屏就能测协议与事件流**；
- 里程碑式长跑：每 5 秒自动推进 + 抓 5 个里程碑，300 秒无人值守；
- 长跑稳定性采样：每 20 秒记 `Process.Responding` 与「点击扫描耗时」，把性能从单点变成分布；
- 点击命中闭环状态机：按下 → 恢复 → 验证 → 重试，并用 `onClick` 标志/反射回读确认「真的点到了」；
- 世界热点点击：手柄模式 + 虚拟鼠标 `WarpCursor` 优先，UI 层再用反射或 `SendInput` 兜底。

> 若未来要做，唯一合理形态是**可选语音后端**：核心仍走 `Repeat`，只把已合成的文本
> 转发给 NVDA 进程；绝不能让 NVDA 插件成为功能入口。

### 3.6 交互形态判定：游戏有没有完全键盘控制

> 权威全文：[`交互形态纪律.md`](交互形态纪律.md) §3（判定）、§4（反模式）、§5（验收）。
> 本节是可执行摘要；**措辞冲突时以纪律文档为准**。

**「完全键盘控制」的定义**：玩家**不装补丁**也能只用键盘完成本作所有需要操作的事 ——
标题菜单、存读档、设置、画廊、选项、确认框、退出，**一个界面都不能漏**；
「完全」按**全流程**算，不是只测标题菜单；判定是**实测结论**，
读代码推断「应该有键盘」不算。

三条路线的判定条件、做法与证据要求：

| 路线 | 判定条件 | 做法（硬边界） | 证据要求 |
|---|---|---|---|
| **A** 已有完全键盘控制 | 不装补丁，全流程纯键盘可完成 | 补丁**只朗读**：不碰输入、焦点、键位；不拦截、不模拟、不加模式开关；朗读由游戏自身事件触发，不靠扫屏判断界面。唯一允许的例外是「重读最近一句」「切换语音后端」这类**朗读侧**热键，且必须避开游戏原生键位 | 「不装补丁纯键盘走通全流程」的操作步骤与结果（录像 / 日志 / 逐步记录） |
| **B** 有键盘但不完全 | 有部分键盘操作，但某些界面 / 操作只能鼠标，或键盘路径走不通（焦点不可见、没有选中态、确认框点不到） | ① 先找游戏自己的入口：键位表 / `Input.GetKeyDown` 所在方法 / `ISubmitHandler` / 按钮点击最终调用的方法 / 游戏自己的选中态字段；用 Harmony 在**游戏自己那条路径**上补缺失的键位或补一次调用。② 补出来的键符合游戏键位习惯、不抢原生键。③ 焦点用游戏自己的机制（`SetSelectedGameObject` 或游戏自己的 hover/selected 字段），视觉高亮 / 音效 / 动画照常。④ **没有模式开关**：进入一个界面键盘就能用。⑤ 补不全的界面**如实登记**为感知 / 操作缺口 | 补丁去掉后该界面恢复原状；装上后键盘路径与游戏原生键盘路径**同形**（同一套焦点、同一套按键语义） |
| **C** 没有键盘控制 / 没有控件模型 | UI Toolkit / 自绘界面 / 无 `Selectable` / KiriKiri Z 这类没有控件模型的界面 | ① 找游戏自己的动作入口（鼠标点击最终调用的方法、按钮 `onClick` 目标、选项选择函数、界面切换函数），**直接调用 / 触发**，不许用 `SendInput` / `PostMessage` / 鼠标坐标模拟。② 尽量借游戏自己的焦点 / 选中数据，没有就维持**最小**选中表示，**不新建 UI 层**（不画 overlay、不弹补丁菜单、不显示「导航中」）。③ **不引入模式开关**，用**上下文自然分流**（界面上有可操作项时方向键移动 / 回车确认，没有时回车推进剧情）：玩家无需学习 vs 模式开关要先学一步。④ 确实做不到「无模式」的，必须在判定文件与发布说明里**明确记为遗留缺陷**，不许当框架默认。⑤ **临时编号菜单**只在「没有任何可调用入口、只能读出屏幕上的选项」时使用，并标注为过渡，找到游戏入口就替换 | 每个界面的「操作入口」都要有反编译实查的方法名或探针事实；「没实测」不许写成「已补全」 |

**禁止**：把 `UiNav` 的「导航模式」（`Tab` 进入 / 退出 + 扫 `Selectable` + 接管 submit）
当作新作的默认交互形态。它是 0.2.x 的**遗留实现**，只为老作逐字节不变而保留
（`CfgMenuNav` 默认 `false`）；新作默认配置里不得出现补丁专属模式键。

**反模式自查（X1–X9，命中任何一条必须给出理由并登记）**：

| 反模式 | 合规范做法 |
|---|---|
| **X1** 用热键进入 / 退出的「导航模式 / 焦点模式 / 浏览模式」 | 无模式；键盘直接可用 |
| **X2** 补丁自己扫屏、自己维护焦点列表 | 用游戏自己的选中态 |
| **X3** 拦截 / 静音游戏 submit、改 `sendNavigationEvents` 来适配补丁 | 仅在修复游戏对读屏的缺陷时最小改，且必须逐作判定（README 专节） |
| **X4** 每帧扫 UI「猜」当前界面 / 当前台词 | 读游戏自己的事件与字段 |
| **X5** 补丁自绘覆盖层、提示条、焦点框、补丁菜单 | 不添可见元素；朗读即输出 |
| **X6** 合成输入（`SendInput` / `PostMessage` / 鼠标坐标）代替调用游戏函数 | 调游戏自己的动作函数 |
| **X7** 让玩家记编号 / 背键位来完成界面操作 | 界面键位符合游戏习惯 |
| **X8** 全局读键无焦点门、作为唯一入口 | 仅窗口无焦点时兜底，默认关 + 焦点门 |
| **X9** 把「界面导航」当新作出厂默认配置 | 新作默认不启用；先做 A/B/C 判定 |

> X3 不是绝对禁止：若游戏完全不用选中态，不修 `sendNavigationEvents` 会让鼠标点过的按钮
> 在按空格推进剧情时被重复点击 —— 那是**修复游戏的读屏缺陷**，不是加功能；
> 判据仍是「关掉补丁后游戏行为不变」，且必须逐作判定。

**验收七问**（P4 逐条回答，写进测试问卷第 2 节与 `docs/交互形态判定.md` §4）：

1. **不按任何补丁专属模式键**，能否只用键盘走完本作主流程？
2. 每个界面里，键盘的「当前项」是否就是游戏自己的选中项（视觉高亮 / 音效在哪，朗读就在哪）？
3. 关掉补丁，游戏键位与行为是否完全不变？
4. 补丁有没有新增画面上看得见的东西？
5. 补丁有没有让玩家背一套游戏里不存在的操作？
6. 朗读是否由游戏事件触发（而不是补丁扫描推断）？
7. 以上任一为「否」时，是否已在文档中如实登记为遗留缺陷？

前 6 条全「是」= A/B/C 任一路线均合格；第 7 条为「是」= 允许带缺陷发布，但必须让玩家知道。

### 3.7 调研先于逆向，原生测试通道先于自造（0.2.7.2 起）

> 这两件事都不写代码，但决定后面「猜多久」与「测多累」。顺序不能反：
> **先查公开资料，再动手逆向；先找游戏自带的测试通道，再考虑自己造跳转工具。**

#### 3.7.1 公开资料检索（P0 第一步）

开始 P0 之前，先检索目标游戏的公开资料：攻略 / 流程说明、截图与界面截图、
商店页与官方说明、社区 wiki、玩法与操作方式、已知的开发者菜单 / 调试模式。
目的不是「照着攻略做补丁」，而是：

- 先建立**界面清单**与**操作预期**（标题 / 存读档 / 设置 / 画廊 / 选项 / 确认框 / 本作特有），
  减少把「我没见过」误判成「游戏里不存在」；
- 知道玩家正常会走哪些界面、哪些操作，避免补丁只覆盖标题菜单；
- 给 P1 探针提供「要重点核实什么」的线索。

**证据纪律**：公开资料只能算线索，不能算证据。版本、语言、平台、模组都可能与本机
不一致；攻略还可能含剧透、错译或过时键位。每一条都要回到**当前版本**本机核实，
按 §7 的证据分级标注（通常低于「资源与配置」），**不许把攻略里的方法名、类名、
键位直接当依据**（铁律 1），也不许因为攻略说「有键盘」就跳过 A/B/C 实测。

**剧透纪律**：检索到的剧情、结局、隐藏要素只用于开发者定位；不许把攻略内容带进
补丁朗读、提示或 README（红线 1 的剧透闸门同样约束开发者自己的产出）。

**落盘**：在作品根的 `无障碍可行性验证.md` §0.1 记录：来源（URL / 平台）、检索日期、
对应版本、可信度（官方 / 社区 / 攻略）、已本机核对 / 未核对。一条都没找到就写
「无公开资料」—— 不许空着，也不许猜。

#### 3.7.2 测试便捷通道（P4 请玩家测试之前）

在把包交给玩家做人工测试之前，按顺序找测试通道：

1. **游戏自带开发者面板 / 调试工具 / 控制台 / 调试模式**（`-debug`、开发者菜单、
   config 开关、测试版分支等）—— 优先用游戏原生方式跳章节 / 给道具 / 改旗标；
   记录开启方式、对存档 / 成就 / 版本的影响、是否需要改游戏文件。用原生通道测试，
   比补丁自己造一套更接近真实运行，也不会把测试代码带进发布包。
2. **没有原生通道时**，再按**逆向难度**与**游戏流程长度**决定是否加「快速跳转测试单元」
   （跳章节 / 场景 / 旗标 / 存档槽），把长流程测试压缩到可接受。流程短、入口好找的作
   不加；流程长到每次测试都要重走半小时的作才值得加。

**测试单元硬约束**（否则就从「测试工具」变成「外挂功能」）：

- 只在**测试构建 / 调试开关**里存在，发布包默认关闭；不注册玩家快捷键，不写进
  `安装说明.md` 的玩家快捷键表，**不算无障碍功能**；
- 不得绕过限时选项、剧透闸门或扩大可达范围（红线 1）；测试跳转只改变「测试起点」，
  不改变发布版的游戏流程；
- 用完即移除，或确认发布构建里默认关闭且玩家无法开启；发布包自检要扫
  「测试跳转 / debug 热键」不出现在发布件里（§5.10 G77）；
- 用开发者面板 / 测试跳转得出的结论仍按 §7 证据分级：只有**玩家正常路径的实机操作**
  能写「已验证」，跳转只用于到达测试位置。

**落盘**：`docs/project_status.md` §1 记「测试便捷通道：开发者面板 / 测试跳转 / 无」，
并注明发布包是否关闭；P4 测试问卷第 0 节同步。

### 3.8 跨作操作逻辑公约（0.2.7.3 起）

> 第 0 条纪律（§3.6）管「形态对不对」；本节管「各作操作是不是长得一样」。
> 全文见 `docs/操作逻辑公约.md`，逐作填写 `docs/操作约定.md`。
> 目标：玩家不需要先判断「这个模组是导航模式派，还是原生操作派」，也不需要每作重学一套键。

**语义固定**（默认键可因冲突改，**语义不许分叉**）：

| 语义 | 默认键 | 语义 | 默认键 |
|---|---|---|---|
| 浏览上一项 / 下一项 | `↑` / `↓` | 激活 | `Enter` / `Space` |
| 调整减小 / 增大 | `←` / `→` | 返回（交还游戏） | `Esc` |
| 重读当前项 | `Backspace` | 剧情选项 | `1`–`9` |
| 沉默 / 重读台词 | `0` / `Backspace` | 切换语音后端 | `Alt+Shift+F9` |

不设「进入 / 退出界面操作」的模式键；`Tab`、`F12` 及游戏原生占用键不用；
调试走配置 / 日志（测试构建才允许临时调试键）。

**激活三级**（`docs/操作逻辑公约.md` §2）：
1. 直接调游戏动作方法（`OnClick` / `ExecuteSelectionLogic` / `Confirm` 等）——首选；
2. 走游戏自己的 Unity UI 事件链：向**真实控件**派发
   `PointerEventData` + `ExecuteEvents.pointerDown/pointerClick/pointerUp`，
   只派发一次，不绕过 `interactable` / 可用性 / 状态判断；
3. 只读扫描 + 编号——最后手段，必须登记。
禁止伪造 OS 输入（`SendInput` / `PostMessage` / 坐标模拟）；X6 只禁这一层，
第 2 级走游戏自身事件链不属于 X6。

**控件与焦点**：当前项 = 游戏自己的选中态；页面控件来自游戏真实字段 / 页面对象 /
真实 pointer-handler 类，**不扫全屏 `Selectable`**；只有游戏会双重移动焦点时才
条件性关 `Navigation`（`Mode.None`），并登记原因。标签来源顺序：
游戏本地化 → 父级 Title/Label → Tooltip → 逐作已核对映射 → 清理后的对象名。

**差异登记**：与公约默认键不同的每一处，写进本作 `docs/操作约定.md`
「本作键位表」（实际键 / 原因 / 证据），并在 `安装说明.md` 给玩家看。
新增或改键前先查四项：游戏键位、Steam 平台键（含 `F12`）、读屏器组合键、
输入法 / 系统占用。冲突处理顺序：改键 > 加修饰键 > 减少功能。

**逐作产物**：P0 起草原作 `docs/操作约定.md`（模板 `docs/templates/操作约定.md`）；
P3 按它定稿；P4 用测试问卷第 2 节核对「语义是否与公约一致、差异是否登记」。
未写操作约定的作品不得宣称「操作已统一」。

## 4. 第二条硬约束：不许扩大可达范围

> **无障碍层绝不能扩大可达范围。**（noexistence CHANGELOG 复盘标题原文）

无障碍层的语义是「把本来能看到/能操作的东西，用朗读与键盘**等价地**呈现」，
**不是**「顺手加功能」。三个仓库里由这条推出的具体规则：

| 规则 | 理由 | 后果 |
|---|---|---|
| **限时选择的倒计时只能拉长，不能取消** | 到点会走这一批最后一条的 `ToNumber`，也就是「什么都不做」的沉默分支 | 取消 = **删掉一个剧情分支** |
| **`RevealableText` 必须同时满足「收到开始打印事件」+「面板确实可见」** | 该控件是复用的，文本会在面板显示前就写入（载入存档 / 加载场景 / 预载剧本） | 否则**在 load 场景念出玩家完全不该听到的内容**（实机已发生） |
| **不可用的选项补丁故意不点** | 游戏把该项标成不可用 | 点它 = 越过游戏自己的分支控制 |
| **剧透闸门** | 无障碍朗读会「读出」视觉上一闪而过的信息 | 必须与正常玩家在同一时刻获得同一信息 |
| **`F4` 剧本跳转默认关闭** | 诊断用热键会让人跳过剧情 | 只在排查时开 |
| **现实时间等待可以跳过，但限时选项绝不跳**〔aliya 实机〕 | 等待只是「等」，跳过 = 帮玩家省时间；限时选项的截止时刻等于替玩家按默认分支 | 跳等待只改「截止时刻/取消发送延迟」，**不写存档字段**；`PlayerCanSkip` 留给游戏自己走正常结束；限时选项拒绝并提示按数字键 |
| **读档静音边界 = 读档流程期间，不是 `GameLoadOver`**〔aliya〕 | 新开局的片头也跑在 `GameLoadOver` 之前，按它静音会把开场白整段吞掉 | 以游戏自己的读档入口（`GameMgr.Load`）为界；读档会把当前消息以 `isNewMsg:true` 重发，按这个信号恢复 |
| **面板必须能用键盘关**〔aliya〕 | 原版只能鼠标点面板外空白关闭，键盘玩家没有出路 | 给 Esc（与游戏自己的关闭路径一致，如把 `display` 设为 `None`），**不新增功能**，只是等价操作 |
| **读不了的图像消息要如实声明**〔aliya〕 | 公告图/漫画格是纯图片，读屏拿不到 | 文档「不做什么」里写明；不要用 OCR 猜（证据与合规都过不去） |

### 4.1 交互形态与可达范围

**外挂形态常伴随扩大可达**：一个「扫全部 `Selectable` 再自己排序」的导航引擎，会扫到
游戏故意隐藏 / 未启用的控件，也能把标成不可用的项激活 —— 那已经越过游戏自己的分支控制，
不是等价呈现。判定办法不变：只要补丁能让玩家做到「不装补丁时做不到的操作」，就算扩大可达。

**但即使没有扩大可达，形态本身也不合格。**「按 `Tab` 进入导航模式、补丁自排焦点表、
接管回车」这三件事，一条可达范围都没扩大，玩家仍然觉得自己在操作**补丁的菜单**，
而不是**游戏的界面**（第 0 条纪律 §1 的七条判据）。所以形态问题不能用「我们没加功能」挡回去。

**新增红线 3（0.2.7.0 起，与红线 1、红线 2 并列）**：
**不得把「导航模式」作为新作的默认交互形态。**
外挂形态的判定与 A/B/C 路线见 §3.6，落点检查见 §6 P8 与 §8 出口清单
（权威表述见 `docs/交互形态纪律.md` §6）。

## 5. 陷阱清单（可直接当 review checklist）

这一节是三个**源仓库** README「几条踩过的坑」+ CHANGELOG 复盘的合并去重；
§5.4 是第 4–7 作（2026-10 ~ 11）新增的增量，两者**每条都有实机事故背景**。
新作开发时逐条对照。案例细节见 [`实践仓库经验-第4至7作.md`](实践仓库经验-第4至7作.md)。

### 5.1 通用（任何一作都会踩）

| # | 陷阱 | 正确做法 |
|---|---|---|
| G1 | **对迭代器方法用 Prefix 返回 false 跳过** → 它返回 `null`，调用方是 `StartCoroutine(...)` | 迭代器方法只能改 `ref` 参数（如 `AutoDestroyAfterTime`） |
| G2 | **Harmony 前缀的参数名必须和运行时一致，不是和反编译结果一致** | 写错名字 → `PatchAll` 抛异常，**其他补丁仍生效**，症状极隐蔽：只有一个功能不工作 |
| G3 | **`Enum.TryParse("0")` 成功但得到 `KeyCode.None`**（数值 0），不是 `Alpha0` | 按键配置项先自己映射单个数字 |
| G4 | **别用 PowerShell 文本 cmdlet 改源码** | `Get-Content -Raw` 在 Windows PowerShell 5.1 下按 ANSI/GBK 读无 BOM 的 UTF-8，中文变乱码。用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($true))` |
| G5 | **`.ps1` 含中文且无 BOM → PowerShell 5.1 按 GBK 解码 → 语法错误** | 构建脚本存 UTF-8 **带 BOM**；或发布脚本**纯 ASCII**（noexistence `release.ps1` 的做法） |
| G6 | **BepInEx 日志是缓冲异步刷盘（约 2 秒一次）** | 用脚本读日志驱动自动化测试时必须等够时间，读到「上一拍」是常态 |
| G7 | **`BepInPlugin` 版本号含字母 → BepInEx 判定 `version is invalid` 并静默跳过整个插件** | 只用纯数字四段（想表达 `0.5.8a` 就写 `0.5.8.1`）；构建脚本里加守卫 |
| G8 | **`BepInPlugin` 版本必须与 `.csproj` 的 `<Version>` 一致** | 构建脚本里校验，不一致直接 exit 1 |
| G9 | **`List.Sort` 比较函数不满足传递性 → 结果任意且不报错** | 严格字典序，不许「近似相等」分支 |
| G10 | **世界坐标 ≠ 屏幕像素**（本作画布世界单位极小） | 先 `RectTransformUtility.WorldToScreenPoint` 换算再分档 |
| G11 | **界面重扫不能定时**（激活按钮后 0.35 秒重扫会撞上场景销毁 → **无 C# 异常的原生崩溃**） | 只扫「下一帧」+ 场景稳定门禁 |
| G12 | **找特定控件别用词边界正则**（`\b(exit\|quit)\b` 对 `ExitButton` / `QuitGame` 两头都错） | 拿实查到的对象名**全等比较** |

### 5.2 IL2CPP 专属（「静默失败」家族，全部不报错）

| # | 陷阱 | 正确做法 |
|---|---|---|
| I1 | **`s.transform is RectTransform` 恒为 `false`，`as Toggle` 恒为 `null`** | Il2CppInterop 给的是包装对象，必须走 `TryCast<T>()`。此坑让 Tab 导航一度扫到 0 个控件 |

#### 5.4.1 补丁纪律（G13–G19）

| # | 现象 / 根因 | 修法 |
|---|---|---|
| G13 | **补丁方法写成嵌套类 → `PatchAll` 静默不打补丁**：不报错，日志仍写「补丁已应用」，但游戏事件一条都抓不到；症状是「热键能用、状态能念、聊天不念」〔aliya 实机〕 | 补丁方法**直接声明在 `Patches` 类体内**；`PatchAll` 后打印 `Harmony.GetPatchedMethods()` 的条数，与离线预检的 N 对照，数量不符就报错 |
| G14 | **「挂上了」≠「被调用」**：`patchedMethods` 只证明 detour 安装成功；游戏改版/分支没走到时补丁一次都不执行〔manosaba 实机〕 | 每个补丁加**命中计数**（或首次命中日志），测试脚本按计数断言；发布前用命中证据而不是挂载证据下结论 |
| G15 | **补了不该补的方法 → 命令永不完成**：给返回 `UniTask` / `Task` / 迭代器 / 非 blittable 结构或接口的方法打 Prefix，可能抛 `MethodAccessException`（实例：`'Naninovel.Async.IAwaiter.get_IsCompleted'`），游戏卡在等待、文字却还在朗读〔manosaba 实机〕 | 补之前先看返回类型：异步/迭代器/非 blittable 一律不补；必须拦就在**命令入口**（发命令的方法）拦，不在等待器上拦 |

| G18 | **一个 `try` 包住全部每帧逻辑**：某个状态抛一次就整局停摆（心跳还在、功能全死）〔aliya 实机〕 | 每帧逻辑**按模块** try/catch；异常按「同一处只记第一次」写独立文件，每次启动清空 |

### 5.6 脚本型引擎的钩子纪律（G46–G55）

Ren'Py 这类「引擎即脚本运行时」的宿主没有编译期类型检查，下面每一条都是**静默失败**。

| # | 现象 / 根因 | 修法 |
|---|---|---|
| G46 | **钩子存在≠会被调用**：`config.all_character_callbacks` 明明有定义，真实 `say` 却从不触发；`config.say_menu_text_filter` 才是会走的那条〔OurBrief 实机〕 | 换官方会调用的钩子；启动时**打点证明被调用**；「钩子函数写完了」不算证据（G14 同族） |

### 5.9 输入 / 生命周期 / 证据补遗（G67–G75）

> 来源：0.2.7.1 对外部协作材料的蒸馏（只收跨作硬缺口，不复述单作细节）。

| # | 陷阱（现象 / 为什么不合格） | 正确做法 |
|---|---|---|
| G67 | **异步加载 / 旧回调晚到**：存读档、面板复用、切页时，上一次请求的回调在新界面才回来；补丁照着旧页面读 / 操作，念错槽位或点错按钮 | 用游戏自己的加载完成 / 绑定事件判定就绪；旧页面回调晚到一律丢弃；页面身份用句柄 / 代次，不用对象名或槽位号当身份 |

| G70 | **图片替代文本拿隐藏文本 / 相邻文本充数**：隐藏台词、调试串、相邻控件文案被当成图片描述；看起来「有描述」，其实说错了图 | 必须核对图片实际内容；隐藏文本与图片可能不符；读不了就如实声明「图片无法描述」，不许 OCR 猜或拿别的文本顶替 |

### P1 · 实机探针（`probe/`）

在写正式插件之前，先做一个**最小探针插件**，把「猜」变成「看」。

> 开工前先看 §3.7：公开资料给出「要重点核实哪些界面」的线索，游戏自带的开发者面板 /
> 调试模式能直接用于取样。两者都不能代替本机实测（公开资料只算线索，开发者面板只算
> 到达测试位置的手段）。

产物（照抄 belfry 的目录）：

```
probe/
  plugin/ProbePlugin.cs          最小 BepInEx 插件：转储运行时事实
  plugin/<Game>A11yProbe.csproj
  run_probe.ps1                  编译 + 部署 + 启动 + 收日志
  run_tab_probe.ps1              针对导航的专项探针
  run_mod_test.ps1               带测试模式跑正式插件
  screenshot.ps1                 截图取证
  installed_manifest.txt         记录安装了哪些文件/版本
  evidence/
    README.md                    ★ 证据索引 + 实测结论
    probe_full_dump.log          补丁点存在性转储
    scene_tree.txt               ★ 运行时场景树（对象名/层级/组件）
```

**探针必须产出三类证据**：

1. **补丁点存在性** → `probe_full_dump.log`：逐个反射确认要挂的方法名与签名真的存在（**belfry 证据 §2「全部补丁点在运行时存在」**）
2. **组件与对象名** → `scene_tree.txt`：`NameAlias` 表与排除名单的**唯一权威依据**
3. **界面视觉事实** → 截图：证明「按钮文字画在图片上、TMP 里没有字」这类判断
4. **界面技术栈** → `ui_stack.txt`：统计 `Selectable` 数量、`UIDocument`/`PanelSettings`
   是否存在、`VisualElement` 树（`visualTree` 递归转储）。三者互斥时以运行时事实为准，
   不看反编译里的死分支（G16）
5. **交互形态事实**（0.2.7.0 起，A/B/C 判定与 B/C 补全的唯一依据）：
   - **游戏自己的键位表 / 输入映射**：键位配置读的是哪个文件/字段、默认值是什么、
     有没有「确认 / 取消 / 移动焦点 / 翻页」的原生键；
   - **游戏自己的选中态与提交路径**：`SetSelectedGameObject` 调用点、
     `ISubmitHandler` / `IPointerClickHandler` 实现者、选中态字段（`EventSystem.currentSelectedGameObject`、
     游戏自己的 hover/selected 字段）、按钮点击最终调用的方法签名；
   - **界面打开 / 关闭事件**：哪个方法在进入界面时被调、哪个在离开时被调
     （朗读挂在这里，不靠每帧扫 UI 猜，§5.8 G62/X4）；
   - **原生占用键**：哪些键游戏自己已经用了（Esc 返回、F5 快进、Ctrl 跳过…），
     补丁补键**不得抢**，朗读侧热键必须避开。

   **探针不是「只把场景树转储一遍」**：`scene_tree.txt` 只能回答「有什么对象」，
   回答不了「键按下去之后走哪条路」。没有上面四条事实，B/C 路线就只能靠猜，
   猜出来的结果就是 §5.8 里那些「像外挂」的实现。产出仍要求可复核：
   方法名 / 字段名 / 键位默认值写进 `probe/evidence/README.md` 与 `docs/交互形态判定.md` §2。

**★ 证据的 IP 红线**（`probe/evidence/README.md` 开篇原文）：

> 本目录只放**不含剧本文本**的证据。
>
> 游戏截图与含台词原文的会话日志**故意不入库** —— 画面本身就是游戏美术资源，
> `[朗读]` 日志行就是剧本原文。仓库的「不包含任何游戏资源」必须**字面成立**。

推论（必须遵守）：

- 探针插件**不记录任何台词文本**，只写类型名、方法名、对象名与控件标签
- 需要复核原始日志时，在本机按 README「如何复现分析」重跑，**不提交**
- 这直接约束了 §2.1 里那条 `[朗读]` 诊断日志：它是**本机排查用**的，
  产出物（`LogOutput.log`）**不得入库**
- 因此 `probe/evidence/` 里只允许放 `scene_tree.txt` 与 `probe_full_dump.log` 这类
  「类型/方法/对象名」级别的转储

**纪律**（`probe/evidence/README.md` 的写法）：

- 证据文件与结论**一起入库**，结论要写「哪台机器、什么时间、什么版本」
- 结论是**断言式**的：「BepInEx 能挂进游戏」「全部补丁点在运行时存在」「标题菜单是纯图片按钮，且带社交链接噪音」
- **开发期发现并修掉的问题也记进去**，不要只留成功记录

### P3 · 逐作实现

顺序建议（按依赖与风险递增）：

1. **`TextProc.cs`** —— 先用 P0 导出的剧本表离线跑清洗规则，**不进游戏就能验证**
2. **台词朗读** —— 只挂「抓住当前台词」一个点，先把最短闭环跑通
3. **选项 + 编号选择 + 重读**（`Choices.cs` / `Reader.cs`）
4. **限时选择** —— 只改 `ref delay`
5. **交互形态实现（A/B/C 判定后）** —— 动手前先看 `docs/交互形态判定.md` 的结论与
   `docs/操作约定.md` 的键位/差异，按路线分头做；界面操作语义一律按
   `docs/操作逻辑公约.md`（↑↓ 浏览 / ←→ 调整 / Enter 激活 / Esc 返回 / Backspace 重读），
   不许另起一套键名或另加模式键（§3.8）：
   - **A 类**（游戏已有完全键盘控制）：**不写一行输入 / 焦点代码**，只挂朗读点；
     这一作没有「导航」这件事，`UiNav` 不接入（§3.6）。
   - **B 类**（有键盘但不完全）：在**游戏自己的输入 / 焦点层**补缺失的键或动作 ——
     游戏自己的键位表 / `Input.GetKeyDown` 所在方法 / `ISubmitHandler` /
     按钮点击最终调用的方法 / `SetSelectedGameObject` 或游戏自己的 hover/selected 字段；
     焦点反馈用游戏自己的高亮 / 音效。**不许新增模式开关**。
   - **C 类**（没有键盘控制 / 没有控件模型）：直接调游戏自己的动作函数（`onClick` 目标、
     选项选择函数、界面切换函数），不许 `SendInput` / `PostMessage` / 坐标模拟；
     用上下文自然分流（界面有可操作项时方向键移动 / 回车确认，没有时回车推进剧情），
     同样**不许新增模式开关**（§3.6）。
   - 补不全的界面**如实登记**到判定文件 §5 与发布说明，不许写成「已补全」（§5.8 G65）。
   - **临时编号菜单只是最后手段**：没有任何可调用入口、只能读出屏幕上的选项时才用，
     且必须标注为过渡，找到游戏入口就替换（§3.2、§3.6 C 类第 5 条）。
   - **先别动平台层**：`platform/` 与 L1 按老作需要整份拷贝即可，形态修正写在 L3（本作）；
     不要为了某一作去改 `UiNav` 的通用行为。UI Toolkit / 无 `Selectable` 的作品
     按 §3.1–§3.2 走 L3 路线。
6. **本作特有形态** —— QTE / 手机 / 手书 / 特殊演出（**每作都会冒出一个**）
7. **现实时间等待与限时选项**（第 4 作起）—— 跳等待 ≠ 推进剧情：只改截止时刻/取消发送延迟，
   不写存档字段；限时选项绝不跳（§4）
8. **感知缺口** —— 浮字/字幕用只读扫描；图像消息如实声明读不了（§3.2）

每加一个补丁点，**先确认它在 `probe_full_dump.log` 里存在**。

**第 8 节是硬要求**：必须验证**关掉补丁时游戏本身行为不变**。

**第 0 条纪律验收（0.2.7.0 起，与第 8 节并列硬要求）**：逐条回答 §3.6 的验收七问，
并把这一作的形态结论落进 `docs/交互形态判定.md` §4：

1. **不按任何补丁专属模式键**，只用键盘走完主流程（标题 → 主界面 → 存读档 → 设置 →
   画廊 → 选项 → 确认框 → 退出），**逐界面**记录结果；
2. **关掉补丁对照**：同一批界面在不装 / 关掉补丁时的键位与行为逐条比对，
   证明「补丁没有改变游戏本身的键盘行为」（红线 2）；
3. **逐界面证据**：每个界面的键盘路径都要有实测记录（截图 / 日志 / 步骤），
   不是只测标题菜单；A 类要有「不装补丁纯键盘走通」的证据，B/C 类要有「补丁关掉即恢复」的证据；
4. 与 `docs/templates/测试问卷.md` 第 2 节「**交互形态验收（第 0 条纪律）**」对齐
   （逐界面勾选 + 七问 + 遗留缺陷登记）；问卷与判定文件的结论**必须一致**，
   不一致以实测为准并回改两边。
5. **操作语义核对**（0.2.7.3 起）：按 `docs/操作逻辑公约.md` 逐项确认
   「浏览 / 调整 / 激活 / 返回 / 重读」语义一致、没有模式键、没有伪造 OS 输入；
   本作键位差异已在 `docs/操作约定.md` 与 `安装说明.md` 逐条登记，玩家可见说明与实测一致。

**任一七问为「否」且未登记遗留缺陷的，不得进 P5 发布。**

**测试前先找便捷通道（0.2.7.2 起，§3.7.2）**：把包交给玩家之前，先确认有没有游戏自带的
开发者面板 / 调试模式可用；没有再用「快速跳转测试单元」。测试通道只进测试构建、发布包
默认关闭、不注册玩家热键；用跳转到达的位置仍要按玩家正常路径复测。记录写进
`docs/project_status.md` §1 与测试问卷第 0 节。

**测试分三层**（第 5/6 作实机，缺一层就会「日志全绿、功能全死」）：

1. **插件内 SelfTest**：IL2CPP 的运行时类型在进程外拿不到（I5），所以断言必须写在插件里，
   启动后第 30 帧左右打印 `SELFTEST SUMMARY`；开关走环境变量或内存开关，
   **不读也不写玩家 `ConfigEntry`**（G30）
2. **进程外 Harness**：`tests/Suite.ps1` 启动游戏 → 标题 → 跳转 → 推进 → 读日志断言 →
   退出码 = 失败数；只读日志与退出码，不碰游戏内存
3. **人工听觉验收**：语速、断句、双播、漏句只能耳朵判定 —— 自动化通过 ≠ 能听

**性能预算先量后改**（G34）：用探针量出 CPU / GPU / 自身每帧开销，再定低性能档；
换档必须全量 `Restore()` → `Apply()`，保存/恢复记账，逐档验证单调。

**自动化边界**（G22 / G24）：合成按键与合成点击在部分新 Input System 游戏里
「返回成功但游戏不认」；能走进程内钩子就走钩子，自动化结果只当辅助证据，
**不能当验收证据**。

**诚实纪律**：CHANGELOG 里明确标注「**尚未实机复测**」的条目是允许的，
把未验证的东西标成已验证是**不允许**的。belfry 的 `0.1.0.1` 就是这么写的：

```markdown
### 复测要点（**尚未实机复测**）
```

### P5 · 构建与打包

**构建脚本流程**（`mod/build.ps1`，照抄骨架）：

```
1/5  检查游戏目录（找不到 <Game>.exe 就 exit 1，提示用 -GameDir 指定）
2/5  获取 BepInEx（本机 dl\ 缓存 → 跨仓库缓存 CacheDir → 联网下载）
3/5  获取 nvdaControllerClient.dll（x64）
4/5  编译 + ★发布前守卫
5/5  组装 package\
```

**Mono / IL2CPP 是两条构建分支，模板必须用 `@@ROUTE@@` 分叉**（只分叉 csproj 不够）：

| | Mono | IL2CPP |
|---|---|---|
| BepInEx | 5.4.23.5 | 6.0.0-be.788 |
| 部署位置 | `BepInEx\plugins\<ns>.dll` | `BepInEx\plugins\<ns>\<ns>.dll`（子目录） |
| 前置 | 无 | 先装机、**运行一次游戏**生成 `interop\` 与 `unity-libs\` |
| 入口 | `BaseUnityPlugin` | `BasePlugin.Load` + `AddComponent<PluginBehaviour>` |
| 额外 | 无 | 叠 patched `Il2CppInterop.Runtime.dll`（按 SHA 配对，见 I6） |

> 构建前**先确认游戏没在运行**：dll 被加载时覆盖会失败或静默用旧文件。
> 生成骨架后先用生成器自带的结构冒烟（清单/csproj XML/别名查重），
> 再在有游戏目录的机器上跑一次 `dotnet build` —— 只查占位符不够（第 5 作实测）。
> 启动方式（launcher / `steam_appid.txt` / Steam 直启）会影响环境变量；
> `DOORSTOP_*` 残留会让插件「突然不加载」，启动脚本要能识别并提示（第 4 作）。

**非 Unity 构建分支**（§3.3 / §3.4）：

- **KiriKiri Z**：`VCVARS32` + `build.cmd`，断言 `VSCMD_ARG_TGT_ARCH=x86`、`/MACHINE:X86`、
  产物 PE `Machine=0x014C`；产物 = 插件 DLL + 注入器。**不要套 BepInEx 流程**：
  这条路线没有 BepInEx、没有 `plugins\` 目录、没有 `interop`。
- **Ren'Py**：无编译步骤；发布前用引擎自带 Python 跑 `tools/check_boot.py` +
  `tools/lint_patch.py`，安装脚本负责清理旧 `.rpyc`。

**★发布前守卫（三条，必须保留）**：

```powershell

[System.Version]::TryParse($pluginVer, [ref]$parsed)   # 否则 BepInEx 静默跳过整个插件
# (2) BepInPlugin 版本必须等于 csproj 的 <Version>
```

**组装规则**：

- `package\` 里**保留自产说明文件**（`安装说明.md` / `常见问题.md`），其余全部重建
  → 说明文件是手写的，不能被构建冲掉
- `nvdaControllerClient.dll` **同时放两处**：`BepInEx\plugins\` **和包根**
  → Mono 的 `DllImport` 会**先查应用目录**

### P6 · 发布

**发布包 = 一个压缩包 + 文档 + licenses，没有安装程序。**

IL2CPP 路线的 `release.ps1` 额外步骤与红线：

- 叠一层**打过补丁的** `Il2CppInterop.Runtime.dll`（上游 PR #277）
- **不打包** `BepInEx\interop` 与 `unity-libs`（首次运行时按本机游戏自动生成，不该由我们分发）
- **不打包** `BepInEx\config\<guid>.cfg`（玩家自己的配置）
- 打包后**自检条目分隔符**：

```powershell
# 绝不要用 Compress-Archive！
# Windows PowerShell 5.1 会委托给 .NET Framework 的 ZipFile.CreateFromDirectory，
# 它用 Path.DirectorySeparatorChar 生成条目名 → 每个条目都是 "BepInEx\core\x.dll"。
# ZIP 规范要求 '/'，Windows 资源管理器 / 7-Zip 甚至 Python 都容忍反斜杠，
# 但 Linux/macOS 的 unzip 不容忍：会解出一堆名字里带反斜杠的平铺文件。
# 用 tools\makezip.ps1 手工构造条目，分隔符恒为 '/'。
```

**发行包逐项自检**（第 7 作实测：从骨架提交起就没通过过，且只黄字警告 = 等于没有）：

1. 插件 dll 存在且版本 = csproj = CHANGELOG 顶部（三处一致）
2. BepInEx 运行时按路线齐全（Mono 5 文件 / IL2CPP 6 core 5 文件）
3. IL2CPP：patched `Il2CppInterop.Runtime.dll` 在位且 SHA 与记录一致
4. `nvdaControllerClient.dll`（x64）在 `BepInEx\plugins\` **和**包根
5. 两份自产文档（`安装说明.md` / `常见问题.md`）
6. 许可证按 `--route` 只带实际随包组件；每作 `THIRD-PARTY-NOTICES` 不得出现
   `THIRD-PARTY-NOTICES.example-*`
7. **不含** `BepInEx\interop`、`unity-libs`、`config\<guid>.cfg`
8. **不含** `dl\`、`bep_dl\`、`nvda_dl\`、`dist\`、`bin\`、`obj\`、测试报告
9. 不含任何剧本文本/截图/`LogOutput.log`（P1 IP 红线）
10. 不含其他作品的模板许可证或路径（`belfry`/`transparenther` 残留）
11. zip 条目分隔符全为 `/`
12. 解包后目录层级与 `安装说明` 写的一致

任一项失败 → `exit 1`，禁止「警告后继续打包」。

**宣传口径（0.2.7.0 起，第 0 条纪律）**：发布说明 / README / CHANGELOG / 商店页面
**不得在没有 A/B/C 判定证据时宣称「完整键盘支持」「全键盘可玩」**。
只有两种情况允许这样写：① `docs/交互形态判定.md` §1 结论为 **A**；
② 结论为 B / C，且判定文件里有**逐界面实测证据**与遗留缺陷清单。
否则如实写「界面键盘覆盖见判定文件：X / Y 界面未覆盖」，并把缺口列进 `常见问题.md`。
「补丁能让你用键盘点界面」不等于「游戏支持键盘」—— 前者是补丁功能，后者才是无差别体验
（§0.5、§3.6、§5.8 G65）。

**非 Unity 路线的发布形态**（与上面 12 项并列，不套用 BepInEx 清单）：

- **KiriKiri Z**：发布包 = 插件 DLL + `plugin\` 文件 + 安装/还原说明。
  **不携带改好的 `data.xp3`**（99.95% 是游戏资源）；安装器必须能从仓库重建（G45）；

**版本方案**（`CHANGELOG.md` 顶部固定两节）：

## 6.5 逐作升级平台层（第 4–10 作实战总结）

已发布的补丁不会自动拿到 Framework 的新平台层；升级一次就会踩到下面每一步。
按顺序做，**不要整目录覆盖**：

0. **先判路线**：只有 Unity（Mono / IL2CPP）才谈「升级平台层」。KiriKiri Z / Ren'Py
   没有 `platform/`，只继承契约与纪律（§3.3–§3.5），**不要硬套 1–8 步**

1. **定版本**：在 Framework 仓库里找到目标 tag，按 tag **逐文件哈希**与逐作副本比对，
   列出真实差异（历史「与某版逐字节一致」的断言已被哈希证伪，见 G33）
2. **换契约**：整份替换 `contract/A11yHost.cs`（只增不改，旧字段保留）；
   补 `Clear()` 复位；逐作 `Plugin.*` 若还残留，先改成 `A11yHost.*`
3. **补 L1 新文件**：按 `tools/l1-files.txt` 拷贝缺失文件并改 namespace
   （`GlobalKeys.cs`、`Hotkey.cs`、`Repeat.cs`、`KeyEdge.cs` 是近年新增的常见缺口）
4. **核对 `Repeat.Push` 调用点**：Framework 版 Push **自己播报**；若逐作旧版是
   「Push 只入缓冲区、调用方再播」，直接替换会**念两遍**（选项最明显）。
   改法：调用方去掉二次播报，或改调 `Note()`（G33）
5. **输入**：窗口能正常拿焦点 → `UseGlobalKeys=false`；必须用全局键 → 置 true 并在
   `Load` 里**主动读一次 `GlobalKeys.Reading`** 打日志（预热，R3）；
   需要屏蔽后台误触时接 `KeyInputAllowed`
6. **可见性与别名**：统一 alpha 阈值（平台 0.05，旧作有 0.5）；`NameAlias`
   忽略大小写查重；`CfgUnknownConfirm` 默认值变化要按本作实测回归（R2）
7. **工具**：更新 `tools/l1-files.txt`；跑 `compile_check.ps1 -GameSrc <真实 UiNav.Game.cs>`；
   `lint_repeat.ps1 -AllowFile Repeat.cs`（逐作布局下必须带）
8. **回归**：探针（补丁点存在 + 命中计数）→ 导航进出 → 选项/重读/限时 →
   测试问卷第 8 节（关掉补丁游戏正常）→ 发行包十二项自检

**升级提交要写清**：从哪个 tag 到哪个 tag、逐文件哈希对比结果、
哪些行为可能变化（Push / 默认配置 / alpha 阈值）。这一节与 §8 平台层清单配合使用。

## 7. 给 AI 协作者的工作方式

> 协作纪律已按读者分轨维护：[`协作指南-与AI协作的人类.md`](协作指南-与AI协作的人类.md) /
> [`协作指南-独立人类开发者.md`](协作指南-独立人类开发者.md) /
> [`协作指南-AI开发者.md`](协作指南-AI开发者.md)。本节保留按阶段的分工表，改动请两处同步。

三个源仓库本身就是「AI 协作开发无障碍补丁」的产物（`SisterOtherParanoiaForNVDA` 的描述写着
「vibe coding experiment」）。第 4–10 作把协作方式又推进了一步。从十作实践里能提炼出的有效分工：

| 阶段 | 交给 AI 的部分 | 必须人工/AI 实测确认的部分 |
|---|---|---|
| P0 | 资源扫描脚本、剧本统计、反编译摘要 | 「这一作最麻烦的三处」的判断 |
| P0（交互形态） | 逐界面清点表草稿、X1–X9 反模式对照、判定文件填表 | **A/B/C 结论 + 逐界面纯键盘实测**（属「必须实测」，AI 不可代判；见铁律 0） |
| P1 | 探针插件与转储脚本 | **探针日志的解读**（不许推测） |
| P2 | 平台层拷贝与改名 | 路线判定（Mono/IL2CPP） |
| P3 | `TextProc` 规则、补丁点代码 | **方法名/签名的真伪**（以反编译为准） |
| P4 | 测试问卷、证据整理 | **实机听感**（朗读顺序、打断时机） |
| P5/P6 | 构建/打包脚本 | 版本号守卫、发布包自检 |
| P7 | README / CHANGELOG / 安装说明草稿 | 合规表述、剧透审查、**文档事实核对** |

**第 4–10 作新增的协作纪律**：

- **审计与修改分离**：多个只读子代理各审一块（平台差异 / 工具链 / 文档漂移 / 跨引擎路线），
  每条结论必须带 `file:line` 证据与 `[已实机验证]/[未验证]` 标签；主代理只负责改
- **跨引擎对照要分轨**：把「能写进通用纪律的部分」与「一次性技巧」分开；
  不要把某一个引擎的权宜之计抬成框架铁律（§3.3–§3.5 的写法就是按这个标准筛的）
- **改动必须先能证伪**：写「已修」前跑 `py_compile` / `compile_check` / 生成骨架冒烟，
  跑不了的如实标「未实机编译」
- **哈希优先于叙事**：版本对齐、冻结层核对一律按 tag 逐文件哈希，不信历史结论（G33）

**铁律 0：先过第 0 条纪律**（0.2.7.0 起，高于下面三条）

> **做出来的东西要像游戏本身就有这个无障碍，不像外挂**：优先用游戏自己的完全键盘控制、
> 与游戏函数交互；游戏没有就手动补全同一套键盘路径；**不许加入「导航模式」这类补丁专属的
> 元操作**。动手前先判 A/B/C（[`交互形态纪律.md`](交互形态纪律.md)、本文 §0.5 / §3.6），
> 判定落 `docs/交互形态判定.md`。

这一条为什么排在三铁律之前：三条铁律管的是「事实真不真」，铁律 0 管的是「方向对不对」。
方向错了，方法名全真、日志全绿，做出来的仍是外挂；而 AI 最容易在 P2/P3 顺手把
「扫 `Selectable` + 接管 submit + 加个模式键」写成默认路径 —— 因为它在旧作里能跑。
**能跑 ≠ 合格。**

**三条铁律**（三作反复验证过的）:

1. **不许猜方法名和对象名** —— 只能来自反编译实查或探针场景树转储。
2. **不许把「没实测」说成「已验证」** —— 未复测就写「**尚未实机复测**」。
3. **别名表每一条都要有依据** —— 在注释里写明来自哪个方法/哪次探针。

**证据分级与 STOP（0.2.7.1 起）**

- **证据分级**（弱 → 强）：读代码 / 反编译摘要 → 资源与配置 → 运行日志 / 探针转储 →
  实机操作。每条结论标注等级；只有实机操作能写「已验证」，其余写「据…推断」「尚未实测」。
  这和铁律 2 是同一件事的细化：不是「测过没有」的二元，而是「证据到哪一级」。
  **公开资料（攻略 / 截图 / wiki）通常低于「资源与配置」**，只能当线索，不能当证据
  （§3.7.1 / G76）。
- **STOP 条件**：同一现象出现两种解释；补丁行为无法用已查证据解释；新证据与既有结论矛盾；
  关键入口（输入 / 焦点 / 动作函数）找不到。此时**停止继续写代码**，把 unknowns 写进
  逐作 `docs/project_status.md` 的「待实机验证 / 遗留缺陷」并询问，而不是带着猜测往下做。
- **STOP 的边界**：只停相关模块，不阻塞独立模块；STOP 是质量动作，不是停工借口 ——
  写清楚「停在哪、缺什么证据、下一步问谁」才算完成 STOP。
- AI 协作者只能整理证据与提出 STOP，不能替人把 STOP 判成「已解决」（铁律 0 / 铁律 2）。
