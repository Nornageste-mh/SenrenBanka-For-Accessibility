# 操作逻辑公约（跨作一致，0.2.7.3 起）

> 这份公约只回答一件事：**玩家在任何一个无障碍模组里，界面操作应当长得一样。**
> 它位于第 0 条纪律之下（`docs/交互形态纪律.md`），不改变「优先用游戏自己的键盘路径」，
> 只把「当需要补键时，补成什么样」统一起来。
>
> 目标：玩家不需要先判断「这个模组是导航模式派，还是原生操作派」；
> 也不需要在每一作重新学一套「上一项 / 下一项 / 确认」。

## 0. 三条总则

1. **语义一致优先于按键完全一致。** 同一件事在所有模组里应当叫同一个名字；
   个别游戏原生占用冲突时，可以换键，但必须在安装说明的「本作差异」里登记。
2. **不覆盖游戏原生键。** 游戏已经有的方向键 / 确认 / 返回，补丁只接管「朗读与焦点播报」，
   不改它的行为；游戏没有的，才在游戏自己的输入/焦点层补。
3. **不设模式开关。** 没有「按 Tab 进入界面操作」这类补丁专属状态。
   界面一打开，键盘直接可用；界面关闭，键盘交还游戏。

## 1. 语义动作表

所有模组的界面操作，按下面这套语义实现。**默认键**是推荐值，不是强制值；
冲突处理见第 5 节。

| 语义 | 默认键 | 行为 | 备注 |
|---|---|---|---|
| 浏览上一项 | `↑` | 焦点移到当前页面上一项，朗读新项 | 若游戏原生就是 `↑`，优先让游戏自己移 |
| 浏览下一项 | `↓` | 焦点移到当前页面下一项，朗读新项 | 同上 |
| 调整减小 | `←` | 仅当当前项是滑块 / 下拉 / 数值时调整；不移动焦点 | 不在普通按钮上响应 |
| 调整增大 | `→` | 同上 | |
| 激活 | `Enter` / `Space` | 对当前项执行一次「游戏原本的点击」 | 一次按键只提交一次；见第 2 节 |
| 返回 | `Esc` | 交还游戏自己的返回 / 关闭处理 | 游戏没有返回路径时才补，并登记 |
| 重读当前项 | `Backspace` | 重读当前控件的名称、类型、值 | 与「重读台词」共用同一出口，不新造队列 |
| 选项 | `1`–`9` | 剧情选项选择 | 既有约定，不属于界面导航 |
| 沉默 / 重读台词 | `0` / `Backspace` | 既有约定 | 与界面语义不冲突 |
| 切换语音后端 | `Alt+Shift+F9` | 既有约定 | 逐作必绑 |

**不要新增的键**：任何「进入/退出界面操作」的键；`Tab`（各游戏含义不同）；
`F12`（Steam 默认截图）；`F1`–`F11` 里游戏原生已占用的键。
调试输出默认走配置 / 日志，不注册玩家热键；只有测试构建才允许临时调试键。

## 2. 激活：三级顺序，不是「一律合成点击」

「像游戏本身就有无障碍」的关键，是激活走**游戏自己的那条路**。按下面顺序选：

1. **直接调用游戏的动作方法 / 字段**
   —— 反编译查到的 `OnClick`、`ExecuteSelectionLogic`、`Select`、`Confirm` 等。
   这是首选，也是证据最强的一级。
2. **走游戏自己的 Unity UI 事件链**
   —— 当动作只存在于 `IPointerClickHandler` / `ISubmitHandler`，没有可调用的公开方法时，
   向**真实控件**派发 `PointerEventData`（`pointerDown` → `pointerClick` → `pointerUp`），
   让游戏自己的事件处理器执行。示意（逐作按实际类型改，不要照抄）：

   ```csharp
   var data = new PointerEventData(EventSystem.current) {
       button = PointerEventData.InputButton.Left,
       pointerClick = target, pointerPress = target, rawPointerPress = target
   };
   ExecuteEvents.Execute(target, data, ExecuteEvents.pointerDownHandler);
   ExecuteEvents.Execute(target, data, ExecuteEvents.pointerClickHandler);
   ExecuteEvents.Execute(target, data, ExecuteEvents.pointerUpHandler);
   ```

   这一级**不是外挂**：它和鼠标点击走同一条游戏路径。但必须满足：
   - 目标控件是游戏自己的真实控件（有游戏的事件处理器），不是补丁伪造的；
   - 只派发一次，不重复、不在每帧派发；
   - 不借它绕过游戏的可用性 / 状态 / 剧透判断（禁用项、锁定项、限时项照旧不可用）。

3. **最后手段：只读扫描 + 编号**
   —— 连事件处理器都拿不到时，才退回「读出屏幕内容 + 编号选择」，
   必须登记为过渡，并写清为什么上不了前两级。

**禁止**：伪造操作系统级输入（`SendInput` / `PostMessage` / 鼠标坐标）、
用宏或连发模拟点击、绕过游戏的 `interactable` / 状态字段强行提交。

> 第 0 条纪律反模式 X6 的准确含义是「伪造 OS 输入代替调用游戏函数」；
> 第 2 级走 Unity 自身事件链不属于 X6，但必须在判定文件里写明用了哪一级、为什么。

## 3. 焦点与朗读

- **当前项 = 游戏自己的选中态**：视觉高亮 / hover / `EventSystem.currentSelectedGameObject`
  在哪，朗读就在哪。补丁不维护第二套游标。
- **进入页面**：优先让游戏自己设初始焦点；补丁只在游戏已经设好之后朗读，
  并**抑制程序化焦点产生的重复播报**（打开页面播一次，不因代码设焦点再播一次）。
- **离开页面**：焦点恢复走游戏原生生命周期与父级关系；不轮询、不用固定延时抢焦点。
- **朗读时机**：焦点变化后播报当前项；激活成功后播报结果（“已勾选 / 已切换到 中文 / 音量 75%”）；
  首项 / 末项可播「第一项 / 最后一项」；空页面播「无可操作项」，不留沉默。
- **延迟朗读**：绑定真实事件（页面关闭、切换、下一次输入）可取消；
  上一页没播完的内容不得串到下一页。
- **标签来源顺序**：游戏本地化文本 → 父级 Title/Label → Tooltip → 逐作已核对的名称映射
  → 清理后的对象名（最后手段）。对象名 / Sprite 名只作证据，不做最终播报。

## 4. 页面控件从哪里来

- **来自游戏真实字段 / 页面自己的控件清单 / 真实 pointer-handler 类**，按页面收集；
  不扫全屏 `Selectable`，不把装饰图、背景、分隔线、不可见容器当控件。
- 只收**有真实点击 / 改值 / 选择处理器**的控件；不可用 / 隐藏的项按游戏状态处理，
  不靠补丁自己猜。
- 游戏原生导航可用时，让游戏自己移动焦点；只有在「游戏会双重移动」时，
  才**条件性**关掉 Unity `Navigation`（`Mode.None`），并登记原因。
- 模态框 / 确认框打开时，只收模态内的控件；关闭后回到父页面并恢复父级焦点。

## 5. 键位冲突与差异登记

新增或改变任何一个界面键之前，先查四项：

1. **游戏自身键位表**（反编译 / 设置页 / Input Manager）—— 游戏原生占用的键不抢；
2. **Steam / 平台键**（`F12` 截图等）—— 不用平台保留键；
3. **读屏器组合键**（NVDA / 争渡 / 系统读屏）—— 不抢读屏器命令；
4. **输入法 / 系统占用**（`Ctrl+Space`、`Alt+Shift` 等）—— 避开。

冲突处理顺序：**改键 > 加修饰键 > 减少功能**；不允许为了保住键位去改游戏原生行为。
每一处与公约默认键不同的地方，写进本作 `docs/操作约定.md` 的「本作差异」表，
并在安装说明里给玩家看。**语义不能分叉**：可以把「浏览下一项」换成 `S`，
但不能在某一作把它叫「确认」。
