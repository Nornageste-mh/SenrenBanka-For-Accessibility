# 《千恋＊万花》交互形态判定（第 0 条纪律）

> **P0 的产物之一，P2 之前必须填完。**
> 依据：`docs/交互形态纪律.md`（本仓库第 0 条纪律）、`docs/无障碍补丁流水线.md` §3.6 / §5.8–§5.9。
> 填写纪律：**判定是实测结论，不是读代码猜的**；未实测就写「尚未实测」。
>
> 本作引擎是 KiriKiri Z（krkrz 1.2.0.3，32 位），不是 Unity：没有 Selectable / EventSystem /
> `PointerEventData`，界面全部是 KAG 图层（`Layer`）。因此本文件的「控件」「焦点」都按
> KAG 的实际对象来写，不套 Unity 术语。

## 1. 结论（三选一）

- [ ] **A. 游戏已有完全键盘控制** → 补丁只做朗读，不碰输入/焦点/键位
- [ ] **B. 有键盘但不完全** → 在游戏自己的输入/焦点层补全（无模式开关）
- [x] **C. 没有键盘控制/没有控件模型** → 制造完全键盘控制，但入口仍是游戏自己的动作函数

**结论**：**C 类，且本版是「遗留形态」——补丁自己维护界面选中项、自己扫屏找控件、
用合成鼠标消息激活，并用 `Tab` 作为进入/退出界面操作的开关。**
这四点分别命中反模式 X2 / X4 / X6 / X1，已逐条登记在 §5。框架 §7 允许老作品保留遗留形态，
但要求写清「保留 ≠ 推荐」；本仓库不把它当作新作品的合规范本。

- 为什么这一版不改：把「合成鼠标点击」换成「直接调用游戏自己的动作入口」是唯一正确方向。
  本轮实机探针已经**打通了第 1 级入口**（见证据第 5 条），但完整迁移要枚举可点层、替换扫屏、
  改掉 `Tab` 开关，还要逐界面读屏验收；半夜无人能听读屏，硬改的风险大于收益，因此列为 0.3.0.0
  的第一件事。可行性记录与迁移分步见 `D:\DSHWorkSpace\_a11y-sb\MIGRATION-FEASIBILITY.md`
  （仓外报告，不入库）与 §5 计划列。
- 判定人 / 日期：项目维护者（Agent 代填） / 2026-11-12
- 证据等级：**源码 + 局部实机**（层树探针、REPL、命中测试）；未做逐界面读屏实机验收。

**证据**（P0 实测步骤摘要）：

1. 引擎与位数：`SenrenBanka.exe` 版本资源 `ProductName = TVP(KIRIKIRI) Z core`、
   `FileVersion = 1.2.0.3`，PE32；无 Managed / il2cpp_data。
2. 输入通道：游戏用 DirectInput 轮询真键盘（不是窗口消息）；`PostMessage` 合成的键
   游戏本身看不见（`tools/sendkey.ps1` 只能被插件的窗口子类收到）。见 `docs/DESIGN.md` §5。
3. 界面模型：没有控件树，只有 KAG 层树。`global.kag.layers` 不存在；
   `kag.primaryLayer` 的 `children` 可遍历（标题菜单按钮、工具栏按钮、TouchUiLayer 子层都能枚举到）。
4. 激活通道：补丁向游戏窗口发 `WM_MOUSEMOVE` + `WM_LBUTTONDOWN/UP`
   （`ClickLogical`，逻辑坐标 1920×1080），由游戏自己命中测试并派发；实机验证过
   能进正片、开回想、选中存档槽。**这是合成 OS 输入，属 X6。**
5. 直接调动作入口的实验（2026-11-12 探针，推翻更早的「入口没打通」结论）：
   - **有效入口**：`layer.onMouseDown(x,y,0,0)` + `layer.onMouseUp(x,y,0,0)`
     （层内局部坐标、button=0、shift=0；只发 down 或只发 up 都不行）。实测能切换设置页签、
     关闭界面、打开标题菜单的 start/continue/load/system/flowchart/language、开关读档/回想/画廊/
     流程图、按确认框的 yes/no。
   - **更上层**：`SystemAction._click()` 连续推进剧情（`data.length` 4→8）；
     `SystemAction._save/_load/_option/_backlog/_vsave/_title` 都能开界面；
     `kag.menu` 菜单项的 `command` 就是动作表达式串，`item.onClick()` 0 参可执行。
   - **仍不通**：存档槽位直接点击（唯一失败点）；选项、滑条拖动、双击、`exit` 未测；
     `layer.onClick` 单独调用只发事件、不产生动作；窗口级 `kag.onMouseDown` 不派发给 UI。
   - 结论：**第 1 级入口已打通，本版尚未迁移**；迁移按 0.3.0.0 排期。
6. 界面键盘：插件窗口过程消费 `Tab`/方向/`Home`/`End`/`PgUp`/`PgDn`/`Esc`/`Backspace`
   并 `return 0`；游戏原生键 `Space`/`Enter`/`R`/按住 `Ctrl` 不被占用。

## 2. 「完全键盘控制」逐界面清点

> 判定口径：**不装补丁时**，只用键盘能不能完成这个界面的操作。
> 「补法」一列：A = 游戏本来就能；B = 在游戏自己的输入/焦点层补全；C = 制造（本作实际做法）。

| 界面 | 不装补丁能否纯键盘完成 | 游戏原生键位 / 焦点机制 | 缺什么 | 补法（A/B/C） | 游戏自身入口（实查） |
|---|---|---|---|---|---|
| 标题菜单（开始/读档/继续/流程图/设置/退出/语言） | 否 | 无焦点链；按钮是 KAG 层，鼠标命中才有反应 | 选中项、浏览、激活 | C（遗留：Tab 进入 + 网格扫屏 + 合成鼠标） | 按钮层 `onMouseDown`+`onMouseUp`（局部坐标，已打通）；`kag.menu` 项的 `command`/`item.onClick()` |
| 剧情对话 | 是 | `Space`/`Enter` 推进、按住 `Ctrl` 快进、`R` 开历史（游戏原生） | 无（朗读另算） | A（补丁只朗读；但非导航模式补丁会把 `Space`/`Enter` 补成一次鼠标点击，见 §5 待实测） | 游戏自己的 DirectInput 轮询 |
| 剧情选项 | 否 | 选项是层，鼠标点；无数字键/方向键选择 | 浏览、编号选择、朗读 | C（补丁：`1`–`9` 选择；方向键 + `Enter` 激活） | 选项层的点击处理 |
| 存读档 | 否 | 槽位是层；无键盘选择 | 浏览、翻页、读/存、破坏性操作确认 | C（遗留：网格扫屏；翻页按钮部分标签不全） | 槽位层与翻页层 |
| 设置 | 否 | 页面模型（`Current.page = 0..7`、每条选项 `Current.cmd(...)`），但文案多为预渲染图片 | 浏览、调值、读当前值 | C（遗留：网格扫屏 + 滑条按百分比点击） | 设置项层的点击处理 |
| 画廊 / 回想 | 否 | 缩略图层；无键盘选择 | 浏览、打开、翻页 | C（遗留：网格扫屏） | 缩略图层点击 |
| 确认框（退出/覆盖存档等） | 否 | 确认按钮是层 | 键盘选择 | C（遗留：网格扫屏；破坏性控件**无二次确认**） | 确认按钮层点击 |
| 流程图（flowchart） | 否 | 节点是层 | 浏览、跳转 | C（遗留：网格扫屏） | 节点层点击 |
| 历史 / 回想文本 | 是（游戏原生 `R` 打开） | 游戏自己的历史层 | 朗读（补丁另做） | A（补丁只读文本） | `kag.historyLayer` |
| 触摸 UI 层（TouchUiLayer 等） | 否 | 移动端样式按钮层 | 键盘选择 | C（遗留：网格扫屏） | 各按钮层点击 |

补充事实（逐条给证据）：

- **游戏有没有自己的选中态 / 焦点链**：没有。KAG 没有「当前选中按钮」概念；
  按钮层的 `visible`/`onClick` 是独立属性，鼠标移到哪由游戏命中测试决定。
  探针：`kag.getPrimaryLayerAt(x,y)` 只能回答「这点上是哪一层」，没有「当前焦点」。
- **游戏有没有自己的键位表 / 输入映射**：有，但只覆盖剧情操作
  （`Space`/`Enter` 推进、按住 `Ctrl` 快进、`R` 历史等），不含界面导航。
  来源：README 与 `docs/DESIGN.md` §5；界面键位表没有公开文档。
- **哪些键被游戏原生占用**：`Space`、`Enter`（含小键盘 Enter）、按住 `Ctrl`、`R`；
  滚轮/鼠标；Steam 平台的 `F12` 截图。补丁不占这些键（`Tab`/方向/`Home`/`End`/`PgUp`/`PgDn`/
  `Esc`/`Backspace` 由插件消费，`Esc` 在非导航模式交还游戏）。
- **界面打开/关闭是否由游戏自己的事件驱动**：是。界面是层的显示/隐藏，
  补丁通过层树与 `kag.selectShowing` 等游戏状态判断，但**扫描是补丁自己触发的**（X4）。
- **公开资料核对**：本仓库尚未做系统公开资料检索（见根 `无障碍可行性验证.md` §0.1，
  标注为待补）；键位与界面结论全部来自本机实测与源码，不引用攻略说法。
- **操作语义是否与公约对齐**：`↑`/`↓` 浏览、`←`/`→` 调值、`Enter`/`Space` 激活、
  `Esc` 返回、`Backspace` 重读 —— 语义一致；但**入口多了一个 `Tab` 模式开关**（X1），
  另外多了 `Home`/`End`/`PgUp`/`PgDn` 四个公约没有的键。差异已逐条写入
  `docs/操作约定.md`，并在安装说明里给玩家看。

## 5. 遗留缺陷（必须如实，没有就写「无」）

| 界面/操作 | 缺什么 | 为什么本版补不上 | 玩家会感知到什么 | 计划 |
