# 《千恋＊万花》交互形态判定（第 0 条纪律）

> **P0 的产物之一，P2 之前必须填完。**
> 依据：`docs/交互形态纪律.md`（本仓库第 0 条纪律）、`docs/无障碍补丁流水线.md` §3.6 / §5.8–§5.9。
> 填写纪律：**判定是实测结论，不是读代码猜的**；未实测就写「尚未实测」。
>
> 本作引擎是 KiriKiri Z（krkrz 1.2.0.3，32 位），不是 Unity：没有 Selectable / EventSystem /
> `PointerEventData`，界面全部是 KAG 图层（`Layer`）。因此本文件的「控件」「焦点」都按
> KAG 的实际对象来写，不套 Unity 术语。

## 1. 结论（三选一）

- [ ] **A. 游戏已有完全键盘控制** → 补丁只做朗读，不碰输入/焦点/键位
- [x] **B. 有键盘但不完全** → 在游戏自己的输入/焦点层补全（无模式开关）
- [x] **C. 没有键盘控制/没有控件模型** → 制造完全键盘控制，但入口仍是游戏自己的动作函数

**结论：B + C（主体是 C，且已去掉模式键）。**

- **为什么是 C**：游戏没有界面控件模型——没有焦点链，也没有可遍历的 Selectable。
  界面全是 KAG 图层，读屏软件看到的是一片空白。补丁必须自己枚举可点层、
  维护一个「现在读到第几项」的朗读索引，界面才能用键盘操作；这部分是「制造」。
- **为什么也是 B**：剧情操作的输入仍走在游戏自己的输入语义上——空格 / 回车推进、
  按住 `Ctrl` 快进、`R` 历史都是游戏原生键，补丁不新增模式；界面补出来的是
  游戏本来没有的那一层键盘控制。
- **A 不成立**：不装补丁时只有剧情能用键盘，标题、存读档、设置等界面没有键盘入口。
- **0.2.0.0 起没有模式键**：界面一出现，`↑` / `↓` 就能浏览、`Enter` 就能激活，
  没有「先按 Tab 进入导航模式」这一步。界面上的「当前项」只是补丁的**朗读索引**
  （不画框、不改游戏状态），属于 C 类允许的「最小选中表示」。
- 判定人 / 日期：项目维护者（Agent 代填） / 2026-11-13（初版 2026-11-12）
- 证据等级：**源码 + 实机冒烟**（2026-11-13 层事件探针、dev-fix4 全流程 + dev-fix5 4 项修复确认、dev 0.2.0.1 两处修复实机验证）；
  尚未由玩家用读屏做逐界面实机验收。

**证据**（P0 实测步骤摘要）：

1. 引擎与位数：`SenrenBanka.exe` 版本资源 `ProductName = TVP(KIRIKIRI) Z core`、
   `FileVersion = 1.2.0.3`，PE32；无 Managed / il2cpp_data。
2. 输入通道：游戏用 DirectInput 轮询真键盘（不是窗口消息）；`PostMessage` 合成的键
   游戏看不见（只能被插件的窗口子类收到）。所以补丁在窗口过程里消费按键，
   再**主动调游戏自己的动作**，而不是「替游戏按一个键」。见 `docs/DESIGN.md` §5。
3. 界面模型：没有控件树，只有 KAG 层树。`global.kag.layers` 不存在；
   `kag.primaryLayer` 的 `children` 可遍历。
4. 枚举方式（2026-11-13 起）：递归遍历游戏层树，取「可见、尺寸合理、自己挂了
   `onMouseDown` 层事件」的层，按阅读顺序排序、按层名与矩形去重并排除噪声层。
   **不再对 1920×1080 打 40 px 网格、不再用 `kag.getPrimaryLayerAt` 猜界面。**
5. 激活入口（2026-11-13 探针，逐界面走通）：直接调层自己的
   `layer.onMouseDown(x,y,0,0)` + `layer.onMouseUp(x,y,0,0)`（层内局部坐标，点宽高中心；
   必须成对且先 down 后 up）。实测能开关标题菜单各按钮、切换设置页签、
   开关存读档 / 回想 / 画廊 / 流程图界面、按确认框的 yes / no；先调
   `SystemAction._save()` / `_load()` 打开界面再点槽位也能读档。
   这是**游戏自己的层点击处理**，不是合成 OS 输入。
6. 剧情推进：`SystemAction._click()` 一次一句；2026-11-13 dev 构建冒烟按 `Enter`
   每次恰好 +1 句，没有双推进。
7. 启动封面：**不需要任何操作**。那段「注意」声明是整屏预渲染图片，不是 KAG 层；
   无输入时约 2 秒自动淡出（2026-11-13 实测：t=14.87 `visible=1` → t=17.18
   `visible=0`），随后约 40 秒自动到标题。最终版代码已删除合成鼠标（`ClickLogical`），
   封面期间补丁只吞键、不做动作。
8. 界面巡检：界面随时可能出现，补丁每 400–500 ms 枚举一次层树；清单连续两轮相同、
   且与上次播报不同时，才播「界面已更新，共 N 项」（已去抖）。
9. 键盘：插件窗口过程消费 `↑` `↓` `Enter` `Space` `Backspace` `1`–`9` `0`
   （`Esc` 仅在补丁有选中项时消费）；`Ctrl` / `R` 等不拦截，原样交还游戏。
   `Tab` / `Home` / `End` / `PgUp` / `PgDn` 不再使用（Tab 模式已删除）。
   冒烟：标题界面 7 项，`↓` 依次念「Language。1 / 7」「新遊戲。2 / 7」，`Enter` 进正片；
   剧情态 `Esc` 清选中并念「回到文字」，无选中时交还游戏；剧情态数字键无动作。
10. 2026-11-13 dev-fix4/5 实机冒烟（游戏 pid 28888）：标题 7 项、`↑`/`↓` 环绕、`Enter` 进正片；
    设置 37 项 / 8 个页签（键盘页 58 项），滑条 `←`/`→` 播报真值；存檔 33 项 / 讀檔 32 项，
    新建 / 覆盖（含确认框）/ 读档成功；确认框只列对话框自己的项；工具栏 21 项可操作
    （但纯键盘唤不出）；`Alt+Shift+F9` 切换后端成功（Tolk 缺失 → 跳过 → NVDA）。
    2026-11-13 dev-fix5 复测 4 项修复：确认框只剩 3 项（是/否/確定，标题 / 正文层不混入）；
    读档后不再多出第 22 项、不再重复播报「介面已更新，共 22 項」（`MusicTitlePopupTip` 装饰层已排除）；
    补扫待定期间按 `Enter` 会在补扫后继续激活（换屏那一拍只播报不激活，有意防误触）；
    音频页滑条念「背景語音 2（滑條）」。
    仍未由玩家用读屏逐界面验收。
11. 2026-11-13 dev 0.2.0.1 两处实机修复：①有配音台词重读缓存不再被界面扫描清空
    （日志：`voiced -> tts suppressed: 「好的，拜託你了！」` → 工具栏消失 → `Backspace`
    → `repeat req: sel=-1 cache=1 len=13`，重读「蕾娜，「好的，拜託你了！」」）；
    ②遮挡过滤——候选中心调 `kag.getPrimaryLayerAt` 取最顶层，命中层不是候选自身/祖先

## 2. 「完全键盘控制」逐界面清点

> 判定口径：**不装补丁时**，只用键盘能不能完成这个界面的操作。
> 本版没有模式键：界面一出现，补全的键盘控制就直接可用。

| 界面 | 不装补丁能否纯键盘完成 | 游戏原生键位 / 焦点机制 | 补丁怎么补（枚举 → 激活） | 覆盖到哪一步 |
|---|---|---|---|---|
| 启动封面「注意」声明 | 否（鼠标点） | 整屏预渲染图，不是 KAG 层；无焦点 | **不需要操作**：无输入约 2 秒自动淡出；补丁只吞 `Enter`/`Space`，不合成点击 | 2026-11-13 实测自动淡出（t=14.87 → 17.18）；朗读固定提示「目前畫面是一段無法朗讀的聲明，約兩秒後會自動關閉，不需要操作。」；随后约 40 秒到标题 |
| 标题菜单（7 项：Language / 新遊戲 / 讀取進度 / 繼續遊戲 / 流程圖 / 系統設置 / 關閉） | 否 | 无焦点链；按钮是 KAG 层，鼠标命中才有反应 | 层树枚举按钮层（按层名过滤）→ 调层 `onMouseDown`+`onMouseUp` | 2026-11-13 dev-fix4/5 冒烟：7 项，`↑`/`↓` 环绕，`Enter` 进正片 |
| 剧情对话 | 是 | `Space`/`Enter` 推进、按住 `Ctrl` 快进、`R` 开历史（游戏原生） | A 类原生键照旧；补丁消费 `Enter`/`Space` 后调 `SystemAction._click()` 一次一句（避免双推进） | dev-fix4/5 冒烟：每次按键恰好 +1 句；`Backspace` 重读当前句；`Esc` 清选中念「回到文字」；剧情态数字键无动作 |

| 触摸 UI 层（TouchUiLayer 等） | 否 | 移动端样式按钮层 | 层树枚举按钮层 → 层事件 | 尚未实机 |

补充事实（逐条给证据）：

- **游戏有没有自己的选中态 / 焦点链**：没有。KAG 没有「当前选中按钮」概念。
  补丁的「当前项」只是朗读索引：不画 UI、不改游戏对象状态、不做命中测试——
  这是 C 类允许的最小表示（见 §3 X2）。
- **游戏有没有自己的键位表 / 输入映射**：有，但只覆盖剧情操作
  （`Space`/`Enter` 推进、按住 `Ctrl` 快进、`R` 历史等），不含界面导航。
  来源：README 与 `docs/DESIGN.md` §5；界面键位没有公开文档。
- **哪些键被游戏原生占用**：`Space`、`Enter`（含小键盘 Enter）、按住 `Ctrl`、`R`；
  滚轮/鼠标；Steam 平台的 `F12` 截图。补丁不拦截 `Ctrl` / `R`；`Enter`/`Space`
  在文本态由补丁调游戏动作推进一句（效果与原生一致，实测不双推进）。
- **界面打开/关闭是否由游戏自己的事件驱动**：是。界面是层的显示/隐藏；
  补丁不再扫屏猜界面，而是枚举游戏自己的层树，界面出现/切换通过
  400–500 ms 巡检 +「清单连续两轮相同」去抖后播报。
- **公开资料核对**：本仓库尚未做系统公开资料检索（见根 `无障碍可行性验证.md` §0.1，
  标注为待补）；键位与界面结论全部来自本机实测与源码，不引用攻略说法。
- **操作语义是否与公约对齐**：`↑`/`↓` 浏览、`←`/`→` 调滑条、`Enter`/`Space` 激活、
  `Esc` 清选中/交还游戏、`Backspace` 重读、`1`–`9` 选选项、`0` 停止朗读——
  与公约一致，且**没有模式键**。差异（界面键盘是补出来的、部分语义位于界面态）逐条写在
  `docs/操作约定.md`。

## 4. 验收（P4 填，对应测试问卷第 2 节）
